# 项目定位阶段

本阶段回答“这是一份什么 RP、它靠什么持续好玩、最终应该叫什么”，不把 RP 写成产品需求文档。

## 允许讨论

- 项目形态：真单人卡、世界/沙盒、群像、多角色、场景包、玩法包、叙事者/主持型或混合型；
- 玩家反复获得的核心乐趣、情绪与节奏；
- 开放探索、关系推进、事件驱动、经营成长、调查解谜等主次关系；
- 整体题材、气质、强度和长期游玩空间；
- 卡名规则：大世界/群像/玩法项目使用能概括整体的标题，真单人卡才默认使用唯一角色名；
- `data.description` 将承担哪种“入口”职责：把模型带入完整项目，不塞任何 NPC 档案。

## 不在本阶段讨论

具体世界规则、NPC 细节、数值、场景、变量、EJS、正则、开场正文和 UI 视觉。用户主动给出的内容只登记到相应阶段。

## 推荐问题批次

第一批聚焦：

1. 希望这份 RP 最常发生什么、最少发生什么？
2. 最主要的乐趣是探索世界、与具体角色相处、推动事件、经营系统还是混合？
3. 希望节奏长期自运转还是围绕明确主线收束？
4. 整体情绪更接近哪几种组合？
5. 项目属于哪种形态，标题应突出世界、玩法、主题还是唯一角色？

每题给出 2–4 个真正不同的方向、影响和推荐。用户选择后生成实际定位片段。

## 推荐源码

```yaml
标题: "雾港夜班"
项目形态: "开放世界群像"
一句话命题: "一座靠夜班维持秩序的海港，在每次潮雾来临时暴露新的异变与利益裂缝。"
核心乐趣:
  - "自由选择调查、交易、结盟或旁观，并承担长期后果"
  - "NPC 在场外继续生活、冲突和改变关系"
  - "同一地点会随时间、势力和事件产生不同面貌"
体验优先级:
  - "世界自运转"
  - "群像关系"
  - "调查与资源选择"
整体气质: "潮湿、暧昧、危险，但不是持续压抑"
游玩跨度: "长期沙盒，可形成阶段性事件线"
卡面入口方向: |-
  你将扮演并调度“雾港夜班”这一完整 RP 项目。世界、人物、事件与规则均由内嵌世界书和运行组件提供；不要把本入口理解成某个 NPC 的人物档案。
```

字段名可以随项目自然调整，不要求硬套固定产品术语。机器字段只保留项目形态和标题等真正影响打包的少数决定。

## 完成门槛

- 项目形态和命名方式明确；
- 核心乐趣、节奏、气质与范围不会互相冲突；
- 能解释为什么这份卡即使没有预设用户角色也能运转；
- `data.description` 的入口职责明确但尚未写成最终全文；
- 当前可选阶段计划与定位不存在明显矛盾，或已更新记录。

## 阶段总汇

给出完整定位稿、卡名、项目形态、核心乐趣、薄弱点和下一阶段推荐。预检阶段已经建立项目记录，因此本阶段结束不再承担“第一次初始化工作区”。
