# 项目定位

若上游脑暴阶段已经形成创作母纲，先直接消费其中的核心体验、玩家进入空间、世界动力、关系张力、典型循环、开局方向和防偏移边界。只询问仍会改变制作合同的真实缺口，不重新要求用户描述“想做什么”“想要什么感觉”，也不把母纲中的开放路线收窄成固定剧情。母纲可能只存在于当前对话；只有用户明确指定的 `创作总纲.md` 才作为创作参考文件读取。

定位只需要确定会实际影响创作的事实：

- 项目是单人物、群像、大世界、玩法型还是混合型；
- 玩家反复获得的核心体验与主要循环；
- 整体气质、内容密度和节奏；
- 适合作为 `data.name` 的标题；
- `data.description` 应传达的项目入口与核心合同；
- 本次确实需要的世界、角色、系统、场景、运行时和 UI 范围。

根据定位缺口进行多轮、多问题访谈，不设固定题数，并给出结合用户材料的推荐。每次用户回答后立即更新实际定位内容。用户完全放权时直接确定方向。阶段总结由主 Agent 在对话中给出，不生成定位账本或总结文件。

判断单人物卡时看项目是否只有一个预先创作的卡内核心角色，不把 `<user>` 当成待创作的配对主角。群像、世界和玩法项目使用整体标题，不用某个 NPC 的姓名冒充项目名。

## 建议式定位访谈

不要只问主题、类型和规模。先提出一个可执行的体验定位，让用户校准：

- **问题**聚焦玩家最想反复获得的感觉、典型一轮会做什么、最不希望项目变成什么；
- **建议**给出一句话核心体验、一个反复循环和一组明确边界；
- **为什么**说明它如何承接现有材料并避免体验发散；
- **影响**指出它会怎样决定世界范围、角色数量、可选系统、开场节奏和项目标题。

标准深度至少写出一个“典型十分钟/三轮 RP”片段来证明定位，不以抽象类型名作为完成。用户只需接受建议、修改重点或指出禁区。
