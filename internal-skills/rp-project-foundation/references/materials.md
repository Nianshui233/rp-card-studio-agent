# 材料与旧卡盘点

读取用户明确提供的材料，只处理当前项目需要的内容。用户授权的仓库、文档和示例可以参考，但最终交付不依赖参考路径。

旧卡修改、审查或转换开始前：

1. 在工作目录保留原始输入副本；
2. 盘点卡面字段、CharacterBook、独立世界书、正则、Tavern Helper、MVU/EJS、HTML、用户条目、未知扩展和媒体；
3. 对每项给出保留、迁移、重写、清理或待确认结论；
4. 识别真实人物、世界、系统和运行组件，不因 `data.name` 自动假定原卡是单人物卡；
5. 清理旧用户资料后提供独立、中文、默认禁用的 `<user>` 空白模板；
6. 原始副本只用于追溯，不进入运行导入清单。

不建立 `project.yaml`、状态镜像、迁移数据库、装配清单或独立盘点 Markdown。盘点结论只在当前对话中报告；工作目录只新增原始输入保真副本和随后真正要维护或交付的内容/代码。

## 建议式材料访谈

盘点后不要把“保留还是删除”全部交给用户。对每个承重材料或组件给出：推荐结论、推荐理由，以及它对风格保真、兼容、返工量或运行链的影响。只有存在真实创作取舍或来源不明时才请求确认；确定的格式迁移和无损修复直接处理。

优先追问用户最想保留的体验、最不满意的表现和绝不能失真的内容，而不是要求用户理解原卡字段。至少用一个代表性片段说明“保留原样”和“保留内核但重写表现”的差别。
