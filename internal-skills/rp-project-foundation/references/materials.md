# 材料与旧卡盘点

本阶段由 `rp-materials-research` 先处理任何用户提供的原始资料；本参考负责旧卡组件盘点和把材料简报交给创作定位。原始资料整理不按字数或文件数量设置触发阈值：一个段落、一个章节、一张旧卡和一批文件都要执行相同的制卡导向提取合同。

## 原始资料处理

只要用户提供文本、文件、旧卡、设定、对白、网页摘录或图片参考，并且当前任务涉及创作、制卡、改写、转换或审查：

1. 保留原始输入，不修改原件；
2. 读取并标记来源、版本、身份和适用阶段；
3. 提取直接事实、角色、地点、组织、事件、关系、规则、风格和玩家入口；
4. 区分核心事实、必须保留、制卡候选、冲突、未知、暂缓和来源不足；
5. 标记每项内容的来源指针，不把推断写成原文事实；
6. 把结果写入 `制作文件/项目记录/materials.json`，并在当前对话显示进度画板；
7. 将材料简报交给定位、世界、角色、系统或开场阶段，不重复抽取或让用户重新描述同一资料。

短资料也必须完成这条链。大资料只改变执行策略：可以分段整理、合并和分批续接，但不得以“太短”跳过整理，也不得以“海量”改变整理合同。

## 主动外部研究

当用户提到已有作品、现实事实、历史/文化背景、版本/改编线或当前宿主事实时，先由 `rp-materials-research` 判断研究触发。默认使用宿主可用的公开搜索/网页读取；用户必须明确要求“不联网”才跳过。没有网络工具时记录 `research.status: blocked`，不声称已搜索。

## 旧卡修改、审查或转换

开始改写前：

1. 在工作目录保留原始输入副本；
2. 盘点卡面字段、CharacterBook、独立世界书、正则、Tavern Helper、MVU 状态实现、EJS 模板实现、MVU→EJS bridge、HTML、用户条目、未知扩展和媒体；
3. 对每项给出保留、迁移、重写、清理或待确认结论；
4. 识别真实人物、世界、系统和运行组件，不因 `data.name` 自动假定原卡是单人物卡；
5. 清理旧用户资料后提供独立、中文、默认禁用的 `<user>` 空白模板；
6. 原始副本只用于追溯，不进入运行导入清单。

旧卡盘点结论和材料整理结果都写入 `制作文件/项目记录/materials.json`、`制作文件/项目记录/authority.md` 和 `制作文件/项目记录/NEXT.md`；不保存完整聊天记录或重复创作正文。

## 建议式材料访谈

整理后不要把“保留还是删除”全部交给用户。对每个承重材料或组件给出推荐结论、理由，以及对风格保真、兼容、返工量或运行链的影响。只有存在真实创作取舍、来源不明或研究冲突时才请求确认；确定的格式迁移和无损修复直接处理。

优先追问用户最想保留的体验、最不满意的表现和绝不能失真的内容，并用代表性片段说明“保留原样”和“保留内核但重写表现”的差别。
