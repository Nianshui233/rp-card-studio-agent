# 材料整理阶段（可选）

本阶段只把用户明确授权的项目材料变成后续可用的创作输入，不创建一套笨重的证据数据库。Agent 自己的示例放在 `assets/examples/`；用户明确提供或授权的外部开源样本也可以进入材料链，记录来源和用途即可，不必反复追加版权提醒。

## 允许讨论

- 哪些文件是用户拥有或明确授权的主材料、辅助参考、旧版本，哪些只是尚未授权的参考；
- 哪些内容必须原样保留，哪些可吸收、改写、压缩或舍弃；用户明确授权的开源参考可以复用或改造其中的代码、结构、文案、设定或资源，但必须按当前项目重新适配，不做未经理解的整包搬运；
- 同一设定冲突时以哪份为准，还是留到所属创作阶段裁决；
- 旧卡、世界书、脚本、HTML、正则和未知扩展怎样只读保存；
- 材料中已经成熟的世界、角色、系统、场景、运行组件分别送往哪里。

不讨论如何新增世界、重塑角色、设计变量或美化 UI。

## 工作方式

1. 只读盘点明确路径，识别格式、编码、版本和可访问性；先标记 `user_material` 或 `reference_only`，未明确授权的路径不得进入装配；
2. 给每份材料一句人能看懂的用途说明；
3. 提取“已确认内容 / 候选内容 / 冲突 / 需要保留的原始组件”；
4. 按目标阶段分组，不把所有事实拆成原子化数据库记录；`reference_only` 只生成抽象技术笔记，不生成可被 assembly 引用的维护源；
5. 原文件保持不动，后续成果写进项目工作区。

## 制作期清理与交付边界

如果新建需求或旧材料含有涉及未成年人的成人性内容，本阶段只做以下处理：

1. 旧卡改造仍保留不可改写的 `original.json` 与 `preserved.json`，以免破坏输入保真；不要在报告中复述、扩写或转化其中的具体内容。
2. 在材料迁移清单中记录 `clean_and_omit`：相关内容不进入新的世界、角色、系统、场景、开场、变量、脚本、前端或世界书；仍有价值的普通身份、亲属、成长、历史和事件事实可以去除该部分后单独迁移。
3. 新卡制作直接不写，不通过“改成变量”“先留占位”“等运行时判断”绕回项目。
4. 清理止于制作和交付。不得把它实现为最终角色卡里的年龄确认、18+ 声明、模型拒绝指令、世界书门禁、MVU/Schema 校验、更新禁路、EJS 判断、正则过滤、UI 警告或 JavaScript 拦截。

材料阶段的正确结论是“从新制品中清理”，不是“在新制品中增加一套持续审查机制”。

## 推荐片段

```yaml
材料:
  - 名称: "旧版角色卡"
    路径: "D:/.../旧卡.json"
    用途: "主材料"
    处理: "只读保留；世界书、正则、脚本和未知扩展先完整拆出"
  - 名称: "补充设定"
    路径: "D:/.../设定.md"
    用途: "补充世界与事件"
    处理: "可重组措辞，不改变明确事实"

优先级:
  - "同名角色资料以旧卡为准"
  - "世界历史以补充设定为准"

待后续处理:
  世界观:
    - "两份材料对潮雾来源冲突，进入世界观阶段裁决"
  运行组件:
    - "保留原正则、Tavern Helper 脚本和完整 HTML，先验证再决定是否改写"
```

## 完成门槛

- 所有输入都知道是什么、用于什么、是否只读；
- 原样保留与可改写范围明确；
- 冲突送到了正确阶段；
- 旧运行组件已完整保存，不因当前工具不理解就删除或重新生成。
