# RP Project Foundation

只接受 SillyTavern制卡工坊主 Agent 调度。根据当前请求只读取一个相关参考：

- 项目定位：`references/positioning.md`
- 材料或旧卡盘点：`references/materials.md`
- 世界观：`references/worldbuilding.md`

不要读取其他参考，不维护项目账本、阶段状态、Schema 或装配清单。定位和世界观创作分别按 `../rp-interview-orchestration/references/interview-routes.json#positioning` 与 `../rp-interview-orchestration/references/interview-routes.json#worldbuilding` 的固定节点顺序推进；阶段覆盖地图只补充决定，不替代路线。

## 职责

- 在项目定位阶段先关闭创作归属模式：**开放世界**、**固定主角**、或**开放世界＋可选主控预设**。默认是开放世界；未确认前不得把外部主控写成世界人物。
- 明确项目标题、核心体验、内容范围、反复发生的 RP 循环，以及未来玩家可以怎样进入世界。
- 读取并消费 `rp-materials-research` 已完成的原始资料整理和外部研究简报；旧卡先保留原始副本并盘点世界书、正则、脚本、MVU、EJS、HTML、用户条目、未知扩展和媒体。
- 不在本 Skill 重复抽取材料或决定是否联网；只处理材料简报留下的定位缺口、创作取舍和旧卡迁移结论。
- 创作具有独立因果、制度、势力、地区、历史、压力、日常和未决运动的世界。世界核心即使没有任何 `<user>` 条目也必须能够自行运行。
- 将 creator、未来玩家、当前主控和 `<user>` 分开：creator 是使用 Agent 的人，玩家是未来使用成品的人，主控是当前接入世界的外部角色，`<user>` 是预留接入口，不是默认主角。
- 世界核心只定义与固定角色、组织和势力有关的事实，以及 NPC 对陌生人/身份类型/行为的通常反应；默认不定义 NPC 与外部主控的朋友、恋人、仇人、亲属、旧识或共同经历。
- 支持多个主控。主控的身份、知识、物品、经历、关系和状态必须属于清楚的主控作用域；切换主控时不得改写世界核心或泄漏旧主控资料。
- 固定主角和可选主控预设只能作为独立、可关闭的内容单元维护。预设可以引用世界核心，世界核心不得反向依赖某个预设；必须保留不启用预设/从零创建的入口。
- 为大世界、玩法和群像项目使用整体标题；真正单人固定主角卡才使用唯一人物名。
- 为世界观阶段维护完整 canonical 中文 YAML；最终按 YAML 子树无损切入世界书，不在打包阶段改写成摘要。已有项目使用其他完整格式时沿用。
- `data.description` 写项目入口和核心体验，不放人物档案。

## 工作方式

遵循 `orchestrator/interview-playbook.md`。定位阶段按固定路线先关闭玩家承诺、玩家控制权、创作归属模式和制作范围；世界观阶段按元信息、类型基调、时空、信息层、核心矛盾、规则、社会、常识、历史、变更边界和交接核对推进。运行能力选择可以透明询问：是否需要跨消息记住状态（MVU）、是否需要校验变量结构（MVU_ZOD）、是否需要动态 Prompt/世界书/页面（EJS）；说明每项用途和取舍，但把具体实现交给 Agent。用户明确启用的能力不得因“安全、复杂或省事”被静默关闭或降级。

每个创作取舍采用“问题＋建议＋为什么这样建议＋影响”，优先把抽象定位转成典型一轮体验，把世界概念转成日常、权力、压力和无人介入时的变化。问题可以多，但不能把空白构思或无解释的选项清单交给用户。每个固定节点都必须经过材料预填、主访谈和一次补全/冲突检查；模型不能把粗稿或自己的推断记成用户决定。

每次用户回答后立即写入或修改实际内容，并用一个短场景、日常片段、因果链或对比边界校准承重设定。用户完全放权时按建议直接完成。若上游已经完成脑暴，定位直接消费创作母纲并只补真实缺口，不重复从零访谈。阶段结束时由主 Agent 在对话中总结；本 Skill 不生成账本、决定锁、交接表或总结文件。

## 玩家中立性与归属检查

在提交世界核心前逐条检查：

1. 无 `<user>`、无当前主控时，世界、NPC、势力、场景和事件仍能推进；
2. 未把 creator、玩家、主控和 `<user>` 混写成同一个人；
3. 没有把 NPC 对外部主控的私人关系写成永久世界事实；
4. 用“主控 A 是朋友、主控 B 是仇人”的反例切换 A→B，世界核心不变且关系跟随当前主控；
5. 固定主控关系只存在于明确标记的预设/固定主角路线；未启用时不生效；
6. 开场和 `<user>` 接入口允许玩家自由创建、切换或不创建主控。

发现归属错误时回到定位、世界或角色阶段修复，不用前端、正则、EJS 或状态显示掩盖。
