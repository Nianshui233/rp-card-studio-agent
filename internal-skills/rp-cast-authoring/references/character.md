# 角色与 NPC 创作

每个卡内角色应具备：

- 身份、外貌识别点和物质条件；
- 想得到什么、害怕失去什么、当前正在做什么；
- 义务、习惯、秘密、矛盾和能力边界；
- 独立日程、社会关系和不在场时的生活；
- 在不同压力与关系中的行为差异；
- 能直接校准模型的具体语言与行为例子；
- 与世界制度、资源和事件的真实连接。

真单人物卡创作唯一核心卡内角色；群像项目按实际需要创作角色网络。NPC 通常保持一个连续世界书条目，不把人格机械拆碎。

避免抽象标签堆砌。用动机、选择、习惯、代价和具体反应说明人格。角色不能停在原地等待 `<user>` 触发，不能无条件偏袒玩家，也不能为了制造冲突突然放弃自保、职责或已建立关系。

NSFW 启用时按人物逻辑完整填写 `sexual_orientation`、`standing`、`fetish`、`preference`、`sex_organs`、`sensitive_areas` 和 `contrast`。关闭时不加载该层。

不创作或预填最终玩家人物。独立 `<user>` 模板保持空白、中文、默认禁用。

## 建议式角色访谈

不要把年龄、外貌、性格标签和背景字段逐项丢给用户。围绕承重人格提出具体建议：角色今天想得到什么、最怕失去什么、如何维持距离或亲近、在利益冲突和被拒绝时怎样选择、公开与私下有什么差别。说明为什么这种行为适合当前世界与体验，以及它会怎样影响对白、关系速度、开场和场外行动。

标准深度至少完成：

- 把一个抽象标签转成可观察动作或语言习惯；
- 写出一个内在矛盾及其代价；
- 用初见、冲突、脆弱、拒绝或不在场生活中的至少两个短场景校准；
- 说明什么表现会让角色“写崩”，作为反向边界。

用户可以只校准已写片段，不需要从零设计人格。

## 行为规则最低合同

承重角色不能只靠“沉稳、毒舌、温柔、危险”等标签维持稳定。行为规则应覆盖项目中真实可能出现的四类压力，允许一条规则同时覆盖多类，也允许用题材等价情境替换：

1. **合作或索取**：被请求帮助、资源、信任或承担额外风险时怎样回应；
2. **冲突或拒绝**：被欺骗、反对、轻视、背叛、拒绝或阻碍时怎样处理；
3. **压力或失败**：危险、损失、时间紧迫、计划失败或旧伤被触及时怎样变化；
4. **价值两难**：两个重要价值、义务、关系或目标无法同时保全时牺牲什么并承担什么代价。

无需机械规定恰好四条，但不能让核心玩法存在无人知道角色会怎么选的整类盲区。某类确实不适用时，用更贴近题材的承重情境替换，而不是删除压力验证。

每条规则满足：

- `trigger` 是外部可判断的事件、事实或关系变化，不写“感到悲伤”这类无法从场景确认的纯内心状态；
- `action` 是第三方能观察到的动作、语言、选择、回避或资源投入，不重述 trigger；
- `reason`、`condition`、`cost` 至少有一项提供额外信息，只保留真实需要的项，不为填模板同时制造空字段；
- 规则能追溯到价值、恐惧、底线、义务、经历或具体关系；
- 同一角色的行为规则、关系态度、日程和自保逻辑不得互相否定。

## 跨字段一致性

定稿和重大修改后检查：

- **价值→行为**：价值排序中至少两个真实取舍在行为规则中有可观察表现；排序不是装饰口号。
- **恐惧→压力**：主要恐惧在 `stress_response` 中有对应泄露、回避、控制或补偿行为。
- **底线→反向边界**：每条 `taboos` 在 `anti_ooc.never` 中有直接对应；额外 never 项能从价值、义务或明确经历推出。
- **内在冲突→两难**：`internal_conflict` 至少在一个无法轻易两全的场景中被证明，并写清选择代价。
- **态度→行为**：对亲近者、陌生人、敌手、权威和项目自定义关系的表现不能与通用行为规则冲突；差异必须有关系依据。
- **背景→当下**：背景只保留会影响当前目标、恐惧、底线、能力或关系的事实，不把关键行为逻辑埋在履历叙述里。
- **语言→台词**：语气、句式、用词、禁用表达、称呼和情绪变化必须由不同情境台词证明；例句用于校准，不供模型机械复读。
- **知识→信息层**：角色只知道世界、身份、关系和事件允许知道的内容；错误认知与 GM 秘密分开。
- **成长→事件门槛**：成长方向可以开放，但核心价值、底线和关系不能无事件依据突然翻转。

## 修改时的级联检查

修改一个承重字段时同步检查真实受影响内容：

- `psychology.values` → 行为理由、底线、优先级、成长方向；
- `psychology.fears` → 压力反应、回避和失控表现；
- `psychology.taboos` → `anti_ooc.never` 与价值两难；
- `behavior.rules` → 关系态度、开场反应和场外行动；
- `speech.style/rules` → 台词、压力语言和称呼；
- `background` 或世界位置 → 动机、能力、知识、义务、资源和关系；
- 日程、义务或计划 → 场景出现条件、无人介入时的下一步和开场可用时间窗。

确定性级联直接修改实际角色内容；会改变用户已确认人格方向时，使用“问题＋建议＋为什么＋影响”让用户校准。不要建立变更日志或角色账本。

## 完成门槛

- 角色在日常、冲突、失败和价值两难中都有可推演选择；
- 价值、恐惧、底线、行为、关系和语言相互证明而非平行堆字段；
- 至少两个具体场景能让用户判断“像不像这个人”；
- 角色在不出场时仍有日程、计划、义务和失败后果；
- 角色知识、能力和资源没有越过世界规则；
- 已明确会写崩角色的反向边界，并能由 `anti_ooc` 或等价内容约束；
- 下游场景、系统和开场可直接使用该角色，不需要重新发明其反应逻辑。
