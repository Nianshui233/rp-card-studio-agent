# 角色阶段

本阶段先盘点完整 RP 包是否需要固定、预先创作的角色；有则把每个角色写成拥有自身生活、职责、关系、计划和节奏的决策者，无则锁定空角色清单并当轮完成，不伪造占位角色。真正的单人卡或明确有核心锚点的项目可以有一个 `primary_character`；世界、群像、叙事者或动态生成人物的玩法项目可以没有固定主角色，部分模式也可以没有任何角色源码。`primary_character` 只表示叙事锚点，不表示该角色拥有整包，也不会让世界/玩法项目改用角色名。所有具名角色默认都是各自独立的 CharacterBook 内容模块。

本阶段只决定“有哪些角色、是否存在叙事锚点、每个人物包含什么内容”，不把任何角色塞进卡面 `description`，也不决定 CharacterBook 宿主参数。角色条目的常驻/关键词策略、插入位置、深度、顺序、概率、扫描深度和递归全部留到整合交付阶段。

这里的角色清单永远不包含 `<user>`。即使是真单人卡，本阶段也只设计那一个卡内角色/NPC，不询问用户准备扮演什么人，也不生成“与该角色最匹配的主控”。用户角色只保留项目适配的空白字段合同，具体值由最终游玩者在开场前端或世界书中自行填写。

## RP 角色架构原则

- **角色是决策者，不是属性集合**：角色核心由动机、恐惧、价值排序、底线和内在冲突组成；这些内容必须能解释其选择。
- **把性格写成可观察行为**：避免只写“温柔、神秘、勇敢”。改写成“谁触发了什么 → 角色做什么 → 语言怎样变化 → 接受什么代价”。
- **覆盖关键场景**：行为规则至少考虑合作、冲突、压力与道德两难；关系态度区分亲近者、陌生人、敌人和权威。
- **语言层互相印证**：语气、句式、词汇、称呼、禁用表达、情绪变化和校准台词必须指向同一个人，而不是几组互不相干的风格标签。
- **背景只保留有用因果**：出身和转折只写会解释当前目标、恐惧、底线或行为的部分，不把角色卡写成传记小说。
- **角色先有自己的生活**：为人物建立职责、日程、私人生活、可调动资源、真实依赖和正在推进的计划；出场是其人生的一部分，不是存在的起点。
- **离开镜头仍会行动**：明确下一步、期限、成功条件、失败后果和场外行动。没有新的直接互动时，人物仍会工作、休息、联系他人、履行义务、改变计划并承受世界变化。
- **关系网不只服务主线**：角色应与其他人物、组织和社会位置形成多向关系，能主动拒绝、离开、隐瞒、求助或优先处理自己的事务。
- **反 OOC 来自角色逻辑**：`anti_ooc.always` 与 `never` 应能从价值排序和底线推导；未知场景从动机与价值外推，不靠“始终保持人设”这种空话。
- **推断要有身份**：普通模式下，尚未由用户锁定的补全在片段说明中标注“AI 补全候选”；完全放权范围内则由 AI 决定、报告理由并直接锁定，不留下反复确认用的占位符。

## 角色因果审计

字段齐全不代表人物成立。每轮合并人物片段后，检查下面的因果映射；发现断链时先修人物逻辑，不要用更多形容词掩盖。

| 来源 | 必须能解释或映射到 | 检查方式 |
| --- | --- | --- |
| `psychology.values` | 至少两条关键行为取舍、底线或关系优先级 | 把两个重要价值放进同一两难，看角色能否稳定选择并接受代价 |
| `psychology.fears` | 压力反应、回避、过度补偿或内在冲突 | 恐惧不能只存在于档案里，触及时应改变可观察行为 |
| `psychology.taboos` | `anti_ooc.never` 的直接映射 | 每条底线都应有防 OOC 对应；不得出现底线允许而 `never` 无理由禁止的行为 |
| `background.turning_point` | 至少一项当前动机、恐惧、底线或行为模式 | 背景只保留仍在塑造当前选择的因果，不写无效履历 |
| `behavior.rules` | 对应价值、条件、理由或代价 | `trigger` 可从外部判断，`action` 可被观察，说明不能只是重复动作 |
| `speech.style` 与 `speech.rules` | 校准台词、称呼和情绪变化 | 台词要实际体现规则；压力语言不能和 `emotion_shift` 自相矛盾 |
| `relationships` | 态度变化、利益、依赖和不会瞬间跨越的限制 | 关系不能因为一次互动无条件跳级，也不能吞没人物其他生活 |
| `nsfw`（启用时） | 身体事实、关系态度、心理与情境行为 | `contrast` 应有心理依据，`preference`、`standing` 与日常人格的关系要可解释而非套用标签 |

行为规则仍应覆盖合作、冲突、压力和道德两难，但不要为了凑数写四条近义反应。每类规则都应让人物在一种真实压力下暴露不同侧面。

语言校准至少要覆盖：常态交流、关系靠近或疏远、压力上升。台词是验收样本，不是让游玩模型机械复读的口头禅库。

新建人物源码使用 `character.schema.json 1.2.0` 和 [character.yaml](../../../assets/templates/character.yaml)。已有项目的数据版本兼容属于 Forge 的项目保真能力，不代表保留旧单体 Agent 工作流。

## 本阶段产物

先形成角色资产清单。定位允许零固定角色且用户选择不预制人物时，清单为空、`source_manifest.characters: []`，不读取人物模板，也不生成空壳角色文件；随后直接进入本阶段总汇。存在角色时，角色源码按人物拆分，默认一个具名角色一份独立源码。每个角色至少形成：

当前 Forge 解包只把完整旧卡保留在项目级 `src/import/original.json`，不会根据 `data.name` 自动生成人物。若较早版本项目中已有 `role: pending` 候选，它只表示“尚未分类”，不是主角色证明。本阶段必须把实际人物改成正式角色类型；若判断原卡其实是世界/玩法包入口而非人物档案，则移除候选，不能把 `pending` 锁进成品。

- 稳定英文机器 ID、中文显示名和 `primary_character | companion | antagonist | npc | ensemble` 分类。
- 外貌、体态、服装和第一印象等可在场景中稳定呈现的外在锚点。
- 当前目标与驱动力、恐惧与失去、价值排序、底线和内在矛盾。
- 合作、冲突、道德两难、压力等触发下的行为、条件、理由与代价。
- 对亲近者、陌生人、敌人、权威和特殊对象的行为、潜台词与语言变化。
- 语气、句式、词汇、口头禅、禁用表达、情绪变化和校准台词。
- 只保留会影响当前行为的出身、转折、未决过去与成长压力点。
- 公开知识、秘密、误解、不可知信息和具体关系变化依据。
- 日常安排、职责、私人生活、可调动资源、依赖对象、当前计划、期限与场外行动。
- 可从心理逻辑推导的 `anti_ooc.always`、`never` 与未知场景处理。

同时形成一份仅用于后续投影的角色分类清单：

- 可选 `primary_character`：仅表示叙事锚点，不表示卡面字段、整包所有权或卡名；完整定义成为独立 CharacterBook 内容模块。
- 每个具名角色（包括 `primary_character` 与 `npc`）：默认各自成为一个 CharacterBook 内容模块，不与其他角色捆成总档案。
- 群体、无名路人或纯职能单位：只有在无法独立触发、单独注入也没有意义时才允许合并，并记录合并理由。

这里的“成为 CharacterBook 内容模块”只表示内容归属和稳定 ID 已确定，不表示已经决定常驻、关键词、插入深度等装配策略。

## 允许问题

可以询问：

- 角色是谁、承担什么叙事功能、在世界中拥有什么职责或身份。
- 已锁定承载模式是否需要一个 `primary_character` 叙事锚点，以及哪些具名角色是独立 NPC；若定位明确为世界、群像或动态角色项目，不强行指定假主角。
- 角色当前想得到什么，失败会失去什么。
- 角色真正需要什么，以及本人是否意识到。
- 多种价值冲突时的优先顺序。
- 恐惧、缺陷、偏见、自我欺骗和不可轻易跨越的底线。
- 在信任、受辱、威胁、失败、亲近、欺骗等刺激下的典型行为。
- 平静、戒备、失控等压力级别下行为如何升级。
- 角色知道、误以为知道和完全不知道的内容。
- 角色与其他人物、组织和社会位置之间的公开关系、私人关系、依赖、矛盾与变化依据。
- 角色今天原本准备做什么，什么事情才足以让其中断安排。
- 角色不在当前场景时会继续推进什么，计划成功或失败后会怎样改变生活。
- 外貌、体态、服装、习惯动作等有助于稳定呈现的特征。
- 语速、词汇、句式、称呼、回避话题和对话策略。
- 哪些为了迎合临时互动而放弃职责、底线、关系网或既有计划的写法会破坏角色一致性。

## 禁止问题

不得询问：

- 新的世界通用力量规则、社会制度、历史事实或势力结构。
- 好感、怀疑等变量的数值范围、增减量、阈值和公式。
- 地点拓扑、门禁、线索位置或事件时间表。
- MVU 字段路径、更新协议、EJS 或脚本实现。
- 全局叙事视角、回复篇幅、排版规则或开场白正文。
- 状态栏布局、颜色、组件或交互。
- `data.personality`、`data.scenario` 等高级定义字段如何分摊人物内容。
- CharacterBook 激活模式、关键词、插入位置、深度、顺序、概率、扫描深度或递归。

角色可以对世界规则有个人理解，但不能借角色设定修改世界规则本身。

## NSFW 条件合并

读取项目预检中已锁定的开关，不在本阶段再次提及或询问：

- 开关为 `enabled` 时，把相关成人维度自然并入人物身体呈现、亲密关系和情境行为结构。启用本身视为用户对该维度的项目级放权，依据已锁定的人格与关系方向补全，不额外建立偏好或限制问卷，不创建独立阶段。
- 开关为 `disabled` 时，不主动加载专项成人 mix-in，也不围绕该维度发起问题；用户材料里已有或人物逻辑自然需要的成熟内容照常保留，不做反向净化。

启用时必须把 `assets/templates/nsfw/character.mixin.yaml` 合并到每一份实际角色源码和最终 CharacterBook 角色条目，并按角色逻辑填充 `sexual_orientation`、`standing`、`fetish`、`preference`、`sex_organs`、`sensitive_areas` 与 `contrast`；不能只在项目账本里记录 enabled。旧卡改造也一样：已有角色经迁移后仍要带完整 `nsfw` 层。关闭时不主动加载该 mix-in；这不构成内容审查或运行时门禁。

用户若主动提供相关角色事实，可以直接纳入对应人物结构，但不要由此发起追问。

## 建议轮次

### 第一轮：身份与戏剧功能

询问 3 到 6 项：

1. 角色在项目中的功能。
2. 可选叙事锚点与具名角色清单。
3. 当前外在目标与失败利害。
4. 在世界中的职业、群体、社会位置与既有关系网。
5. 最容易被辨认的第一印象。
6. 多角色项目中各自的差异化职责。

### 第二轮：内在决策引擎

询问：

- 内在需要和自我认知差距。
- 价值优先级。
- 恐惧、弱点、底线与合理化方式。
- 最容易撕裂角色的两难冲突。

不要只让用户选“温柔/冷淡”。方向应说明不同选择会怎样改变行为。

### 第三轮：生活、计划与场外推进

收集角色的日常节奏、必须履行的义务、可调动资源、真实依赖、私人生活和正在执行的计划。每个重要计划至少写明下一步、期限、成功条件与失败后果，并回答：角色离开当前场景后会继续做什么，什么事情才足以打断原定安排。

### 第四轮：行为与压力

为高频刺激建立“观察 -> 判断 -> 行动 -> 后果”的模式，并写出从平静到高压的升级阶梯。把会造成 OOC 的捷径明确列为禁止行为。

### 第五轮：知识、关系与语言

确定信息边界、与其他人物和组织的关系起点与可变化部分、称呼和表达策略。语言示例只用于校准角色口吻，不提前写叙事阶段的开场白。

### 第六轮：一致性审计（仅按需）

用背叛、示弱、利益诱惑、权威命令、世界规则冲突等情境检查角色是否有稳定裁决依据，并执行“角色因果审计”矩阵。发现数值需求时只登记系统待办。

## 充分性门槛

本阶段整体应满足：

- 角色分类符合已锁定 `card_mode`：真正的单人项目与带锚点项目都至多一个 `primary_character`；世界/群像/动态角色项目可以没有；不存在两个竞争的主锚点，且带锚点项目没有被误判成真正单人卡。
- 空角色项目已由承载模式支持，明确锁定 `source_manifest.characters: []`，且没有占位角色、空壳档案或人物模板残留。
- 每个具名角色都有独立稳定 ID、中文显示名和独立 CharacterBook 内容模块；合并无名群体时有明确理由。
- 没有把其他角色档案、世界规则、系统规则或叙事合同混入某个角色定义，也没有把任何角色预定写入 `data.description`。
- 没有在本阶段询问或锁定任何世界书调度参数。

每个角色都应满足：

- 身份、叙事功能、外在目标和失败利害明确。
- 在世界中的位置、职责、关系网和私人生活明确，不靠某次互动才成立。
- 至少有一项正在推进的计划、一条日常节奏和一个足以改变安排的中断阈值。
- 离开镜头后仍有可执行的下一步，成功、失败与拖延都会产生后果。
- 内在需要与自我认知之间有可表演的关系。
- 价值已有排序，面对冲突可以预测选择。
- 弱点、恐惧、底线和矛盾不会互相抵消。
- 价值、恐惧、底线、背景与行为之间的因果映射能够逐项解释，不存在孤立字段。
- 至少覆盖合作、冲突、压力、道德两难，以及常态与关系变化时的行为模式。
- 知识、误解和秘密分层明确，不会无故知道 GM 信息。
- 重要关系有起点、变化依据和不会瞬间跨越的限制，且不存在唯一关系吞没全部生活的情况。
- 语言规则足以辨认角色，校准台词能证明语气、句式、称呼和情绪变化成立，但不要求固定台词机械复读。
- 每条 `taboo` 都能映射到 `anti_ooc.never`；额外 `never` 能从价值或明确经历推出，不是“始终保持人设”之类空话。
- NSFW 启用时，成人层与身体、心理、关系和行为互相一致，`contrast` 不是脱离角色逻辑的通用反差套话。
- 需要数值化或工程化的事项已路由，而非在本阶段提前实现。
- 条件启用的成人结构已按预检状态自动合并或完全省略。
