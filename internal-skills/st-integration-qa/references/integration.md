# 最终交付与真实宿主验收

本模块直接整理已经完成的内容和运行组件，不使用通用装配器。

## 文件整理

按实际项目需要生成：

- 角色卡 JSON；
- 独立世界书 JSON；
- 正则 JSON；
- Tavern Helper 脚本 JSON/JS；
- 完整自包含 HTML；
- MVU/EJS 文件；
- 简短导入说明。

不要创建空目录、空组件、项目清单数据库或构建报告。世界、NPC、系统、场景和叙事按语义职责写入 CharacterBook；HTML 和正则保持分件交付并建立明确配对。

## 导入顺序

按项目实际组件调整，常见顺序是：

1. 导入角色卡；
2. 导入独立世界书并绑定为角色主世界书；
3. 导入正则；
4. 将配对 HTML 全文放入对应正则替换内容；
5. 导入/启用 Tavern Helper 脚本；
6. MVU 项目先启用唯一 Loader，再按路线启用 Zod Schema 和项目脚本；
7. 导入或启用 EJS/ST-Prompt-Template 条目；
8. 开始首轮对话并执行实际验收。

“世界书文件存在”“已经导入列表”“角色当前绑定该书”必须分别确认。

## 真实 SillyTavern 验收

按实际功能检查：

- 默认和备用开场；
- 主世界书导入、绑定和条目触发；
- 正则的 display/prompt 通道；
- MVU 初始化、更新、持久化和当前楼层读取；
- EJS 生成或渲染；
- HTML 数据、按钮、iframe/父窗口桥和错误回退；
- 编辑、Swipe、重载、聊天切换、旧楼层和重复挂载；
- 窄屏、长中文和软键盘；
- Tavern Helper/MVU/EJS 版本、远程 Loader 和网络依赖；
- 控制台首个因果错误。

创角或 UI 提交使用一个非默认值，确认真实状态或 `<user>` 条目读回已经改变。聊天正文里出现新值不算写入成功。

无法实测时仍可交付候选包，但必须准确列出 `runtime: not_run` 和用户需要手动完成的导入、绑定或粘贴步骤。
