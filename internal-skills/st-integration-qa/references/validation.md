# 最终文件检验

只检查用户工作目录中的实际成品。检验目标是发现会造成无法导入、无法运行、数据丢失或确定断链的问题，不检查项目管理状态，不要求源码清单、构建记录或装配清单。

## 证据状态

- `pass`：已执行检查且通过；
- `fail`：已执行并确认失败；
- `warning`：可以继续，但有已知代价；
- `not_run`：尚未执行；
- `blocked`：缺少环境、依赖或输入。

离线文件通过不等于真实 SillyTavern 运行通过。没有宿主证据时保持 `runtime: not_run`。

## 可阻断问题

- JSON、YAML、JavaScript、EJS、HTML 或正则无法解析；
- 角色卡、世界书、正则或脚本的必需宿主字段损坏；
- 最终文件丢失用户原有未知扩展或未经授权覆盖原件；
- 世界书为空、绑定目标名称不一致或条目调度字段互相矛盾；
- MVU/EJS/UI 已声明启用却缺少真实实现；
- 新 MVU 路线缺少 `[initvar]`、更新协议、唯一 Loader 或必要清理规则；
- 标记、正则、HTML 没有真实生产者/消费者闭环；
- UI 读取错误路径、写入后不读回、按钮确定无响应或事件重复注册；
- 完整/流式技术块泄露到玩家显示或错误提示词通道；
- 交付 HTML 不完整，或依赖需要用户另行拼接的本地 CSS/JS；
- 可导入文件残留工作目录绝对路径、`src/...`、`source_refs`、`content_file`、`replace_file` 等维护引用；
- 旧卡清理后缺少独立、中文、默认禁用的 `<user>` 空白模板；
- 方案要求修改 SillyTavern 或插件本体才能运行。

## 世界书

检查：

- 独立世界书 entries 非空；
- 中文显示名、启用状态、constant/关键词模式、关键词、position、depth、order、概率和递归符合实际用途；
- `at_depth` 有明确 depth 和 role；
- EJS 按名调用条目默认关闭且不参与普通关键词扫描；
- 世界、NPC、系统和场景按语义保持连续，不被机械拆碎；
- 项目只有一个 canonical `<user>` 档案条目，动态状态不写成永久静态事实。

“文件存在”“已导入酒馆”“已绑定角色”是三项不同证据。

## MVU / EJS

只检查实际使用的路线：

- `native_schema` 不强制 Zod；`mvu_zod` 或明确的 `hybrid` 才检查 `registerMvuSchema`；
- `[initvar]` 有真实初值并进入名称含 `[initvar]` 的世界书条目；
- Schema、初值、更新规则、回复输出格式和 UI 路径一致；
- 卡内 MagVarUpdate 只有一个 Loader；
- `<UpdateVariable>` 与 `<StatusPlaceHolderImpl/>` 的 prompt/display 处理按实际路线闭合；
- 完整更新块和流式半块都按预期隐藏；
- EJS 文件、执行阶段、变量作用域、按名调用条目和失败回退明确；
- EJS 与 MVU 联动有明确方向和路径；
- 创角或 UI 写入后能从真实状态读回非默认值。

## 正则

检查真实 SillyTavern 字段：稳定 ID、中文 `scriptName`、可编译 `/pattern/flags`、placement、depth、`markdownOnly`、`promptOnly`、`runOnEdit` 和替换内容。

按实际协议决定是否需要 display、prompt、完整块隐藏和流式半块隐藏，不生成固定数量套装。每条正则都要能反向找到真实生产者。

## UI

- 最终文件是完整、自包含 HTML；
- 可见字段有自然中文、真实数据源和空/错/加载状态；
- 消息 iframe 需要时探测当前窗口和父窗口；
- 按钮有真实动作、反馈和失败回退；
- 重载、编辑、Swipe、切换聊天和重复挂载不会确定性出错；
- 窄屏和长中文可用；
- 不创建聊天外层的页面级常驻面板。

UI 规模按用户实际需求判断，不按导航数、按钮数、代码行数或固定“轻型基线”阻断。

## 交付包

只包含项目实际使用的组件。检查角色卡、独立世界书、正则、脚本、HTML 和 MVU/EJS 文件是否分别可导入或可使用，并提供简短导入顺序。未使用的组件和原始保真副本不进入导入清单。
