# 校验与证据

校验只阻止会让产物损坏、数据丢失、功能确定断裂或违反用户明确要求的问题。个人本地项目不套用公开商业产品的威胁模型；版本耦合、私有 API、远程依赖和复杂 JavaScript应如实报告，但不因“不够保守”自动阻断。

生命周期决定严重度：`draft` 中尚未创作的组件属于待办或警告；阶段 `locked`、最终整合或制品声称路线完成后，缺少承重组件才阻断。已经存在但语法损坏、引用越界、数据丢失或发生真实冲突的问题不因草稿状态而隐藏。

## 证据状态

- `pass`：有足够证据确认。
- `fail`：已确认失败。
- `warning`：可继续，但存在已知代价或未覆盖项。
- `not_run`：尚未执行。
- `blocked`：缺少环境、依赖或输入，无法执行。

离线构建通过不等于真实 SillyTavern 运行通过。没有真实宿主证据时，运行状态必须保持 `not_run`。

## 可以阻断的情况

- 已实际执行的解析器确认 YAML、JSON、JavaScript、EJS、HTML 或正则存在语法错误；未执行的类型保持 `not_run`，不能凭文件存在宣称通过；
- 最终角色卡或世界书无法重新解析；
- 构建会覆盖未授权的原文件、未知导入字段或用户已有扩展；
- CharacterBook ID、世界书 uid、正则 ID 或脚本 ID 发生真实冲突；
- 条目来源不存在，且回退策略不是明确的 `skip`；
- 条目触发、插入、概率、扫描深度或递归字段缺失/互相矛盾；
- 非宿主支持的位置、可见性或路由被悄悄当成有效提示词条目；
- MVU/EJS/UI 已启用但没有实际源文件，只有概念配置或空占位；
- 锁定整合后独立世界书仍为空，或已有世界、人物、系统、场景源码却没有任何世界书装配条目；
- 锁定的新建 MVU 路线缺少真实初始值，或最终 CharacterBook 没有名称含 `[initvar]` 的有效初始化条目；
- 完整 HTML/JS/EJS 在装配后被截断、转义破坏或改写；
- UI 明确读取错误数据、按钮确定无响应、事件重复注册导致确定故障；
- 锁定的开场/持续 UI 声明为中型、重型或超重型，但实际 HTML 缺少相应导航、数据、复合交互、反馈、宿主联动或响应式能力；
- MVU/Tavern Helper 消息前端只访问当前 `window`，而项目运行契约声明全局对象位于 `window.parent`，导致 UI 只能显示空壳或默认值；
- 选择正则替换路线的锁定 UI 已有捕获正则和 HTML，但没有任何真实标记/XML生产者；
- 正则无法编译、placement/深度非法，或完整/流式技术块会泄露到错误通道；
- 默认与备选开场无法正确投影；
- 声明开场与持续UI完全分离却混用同一标记，或所选开场渲染路线缺少自己的真实承重组件；
- 开场创角表单声明会改变运行时数据，却没有 `creation_bridge` 的字段绑定、真实提交路线或回读证据；
- 卡名和项目类型明显冲突，或 `data.description` 被误写成 NPC 档案；
- 用户明确禁止的页面级常驻状态面板被创建；
- 方案要求修改 SillyTavern 或插件本体才能工作；
- 项目包任一 JSON 往返破坏语义，或组件清单与实际文件不一致。

## 世界书校验

每个装配条目都必须显式决定：

- 中文显示名；
- 是否启用；
- `constant` 或关键词触发；
- 主关键词、次关键词、selective 与逻辑；
- 大小写和整词匹配；
- 插入位置、深度、角色与顺序；
- 触发概率；
- 扫描深度；
- 入站递归、出站递归和递归延迟；
- 预算行为；
- 来源和回退。

还要检查：

- 重复显示名或相同 order 在 SillyTavern 中是合法的；只在它们造成已证实的调度错误时提示，不作为通用阻断；
- `at_depth` 必须有明确深度与角色；
- 常驻/关键词模式以 `activation.mode` 为实际语义；SillyTavern 导出的常驻条目可以保留主关键词、次关键词或 `selective` 默认字段，不因这些兼容字段本身阻断；
- 关键词条目至少有主关键词；
- 递归延迟不能与阻止入站递归矛盾；
- 内容型世界书不应把所有条目同时封死双向递归；
- standalone 世界书对象键必须与数值 uid 一致；
- 导入条目和新条目不能互相覆盖；
- 独立世界书 entries 非空，且项目清单记录正确的目标角色；
- “世界书文件已生成”“书已进入 SillyTavern 世界书列表”“角色已绑定该书”分别记录，不能用前一项代替后一项。

世界观按主题切片；NPC 通常保持完整；系统、场景与叙事按职责保持连续。正文应是可读 YAML/文本，不机械转成 JSON。

## MVU/EJS 校验

只校验项目真实选择的实现：

- 初始变量文件存在且与 Schema JS 一致；
- 所有新 MVU 路线都把真实初始值装入名称含 `[initvar]` 的 CharacterBook 条目；维护源不限定为文件；MVU_ZOD 不代替初始值；
- 开场 `<initvar>` 只作为已挂载主世界书初始化后的覆盖层，不作为无世界书时的独立启动方案；
- Schema/Zod 脚本是实际可装入的 JavaScript；
- 更新规则和回复输出格式与变量路径一致；
- EJS 文件语法、依赖、读取路径和目标条目明确；
- Tavern Helper 脚本内容原样进入卡内扩展；
- MVU 变量路线的 Tavern Helper ScriptFolder 至少有真实 `mvu_loader` 与 `mvu_schema` 两个基础节点：前者包含 MagVarUpdate 固定 import，后者包含 `registerMvuSchema` 固定 import，且顺序、依赖和来源文件可追溯；
- 变量更新块的完整与流式正则符合本卡实际标签；
- 技术测试卡可以缩小内容与 UI 规模，但不能省略所选技术路线的承重组件；聊天消息中的变量更新块必须同时验证“完整块”和“流式未闭合块”在玩家显示层不可见；
- 默认由卡内正则承担变量块显示清理；若改由 MVU 框架、宿主全局正则或既有实现承担，必须在 `mvu.update_strategy.display_cleanup` 记录模式与实际证据，不能只凭“框架应该会处理”跳过；
- 初始化块、状态块、提示词和显示通道不会互相泄漏；
- 开场创角提交后至少有一项非默认值能从实际 MVU/API/项目状态读回；仅聊天正文或 `createChatMessages({ data: ... })` 附件出现新值不算通过；
- 每个 UI surface 的生产者、产出频率、来源与证据明确；模型每轮输出标记必须由常驻、模型可见的 CharacterBook 条目明确命令，非 MVU 状态栏还要定义完整 XML 数据块；
- 已有成熟实现迁移后保持原语义。

Forge 不生成 MVU 引擎、Schema、Guard、EJS 或固定回复合同。缺少这些源文件时应要求补齐实际实现，而不是自动造一个替代品。

## 正则校验

对每条角色正则检查真实 SillyTavern 字段：

- 稳定 `id` 与中文 `scriptName`；
- 可编译的 `/pattern/flags`；
- HTML 正则配置与对应完整 HTML 文件一一配对，用户粘贴后的 `replaceString` 完整；
- `placement`、`disabled`、`markdownOnly`、`promptOnly`、`runOnEdit`、`substituteRegex`；
- `minDepth` 与 `maxDepth`；
- 重复 ID 和冲突覆盖策略。

按项目协议检查是否需要以下成组规则：

1. display：把开局/状态标记替换为完整 HTML；
2. prompt：删除纯界面内容或替换成短模型说明；
3. 完整变量块隐藏：匹配已经闭合的更新块；
4. 流式变量块隐藏：匹配尚未闭合的更新块；

开场前端与持续状态前端分别记录职责。正则路线需要 opening/marker/HTML/display/prompt 链；脚本、EJS、inline、framework 或 existing 路线只校验自己实际选择的链。共享源码、开场转运行和0层统一应用必须显式声明关系，不因共享实现自动判错。
5. 其他独立剧情块：检定、通知、选择等。

这不是固定数量清单。没有某类协议就不生成相应正则；存在协议时则必须覆盖其真实生命周期。

## UI 校验

- UI 是完整、项目专属的 HTML/CSS/JS，不是通用仪表盘拼装；
- 默认把 UI 当浏览器应用开发：结构、CSS、状态、渲染、交互、宿主适配和模拟数据可分别维护，最终才构建成自包含 HTML；
- `multi_file_html` 必须有 `ui-app.yaml`；其 `output` 与 `opening_ui.file` 或 `status_ui.surfaces[].file` 指向同一制品；
- `ui-build` 重建结果与当前运行 HTML 完全一致，不存在 `ui.app_stale`；
- 中型及以上应以完整模拟状态检查满数据、多人物、多事件、长中文、空态和错误态；模拟数据不进入真实运行数据链；
- 一组共享数据和导航的功能尽量位于同一个完整功能面；
- 可见字段有中文标签、真实数据源、格式化和空/错数据状态；
- 轻型达到技能内置原创样本所代表的体验下限：完整内部导航、多类数据视图、至少一种信息操作、至少一种真实宿主行动、反馈/回退、响应式、真实数据绑定和项目专属主题；只有少量静态数值的小面板不能冒充轻型；
- `experience_evidence` 用于记录玩家可见证据与高档位增量，不按字段数量或维度数量阻断构建；
- 不以文件大小、代码行数、页签数或按钮数作为等级门槛，也不接受用堆代码代替真实体验；
- 按钮有真实反馈、失败表现和重复点击处理；
- 支持中文长文本、窄屏、触控、软键盘和减少动画；
- 编辑、Swipe、重载、聊天切换和同消息重复执行不产生确定错误；
- 父页面 DOM、插件对象、私有 API、浏览器存储和远程资源可以使用，但必须登记依赖并真机验证；
- 不创建脱离消息的页面级常驻状态面板。

## 制品校验

默认目标是一个多文件 RP 项目包。检查：

- 制作期排除的涉及未成年人的成人性内容没有进入任何可导入组件；旧卡保真副本只留在维护工作区，不列入导入顺序；
- 没有把制作期清理变成运行时年龄/成年门禁：世界书、系统、MVU/Schema、EJS、脚本、正则和 HTML/JS 中均无 18+ 确认、成年证明字段、拒绝指令、年龄更新守卫、关系禁路或隐藏拦截；
- 角色年龄作为普通事实、成年角色内容和普通的类型/路径/数据完整性校验不因此被误删；这里检查的是夹带的玩法监管，不是清除一切年龄字段；

- `data.name`、`data.description`、开场和 CharacterBook 正确；
- 高级定义只按已决定的策略保留、迁移或清理；
- 用户已有正则、脚本与未知扩展没有丢失；
- 完整 HTML/JS/EJS 与源码一致；
- 模块化 UI 的开发清单、源文件与最终内联 HTML 一致，装配只使用最终构建结果；
- 重新读取、重复构建和 roundtrip 保持幂等；
- 项目包必须包含角色卡、独立世界书、正则、完整 HTML 和所需脚本；不再生成单文件或 PNG 替代交付路线。

## 真实宿主验收

在 SillyTavern 中至少检查：

- 导入角色卡，并执行“Import Card Lore/导入卡片世界书”；
- 确认独立世界书已导入列表，角色当前主世界书也指向它；
- 默认/备选开场；
- 角色正则授权与运行；
- MVU 初始化、更新和读取；
- EJS 生成/渲染；
- HTML 的数据、按钮和宿主联动；
- 编辑、Swipe、重载、聊天切换、窄屏；
- Tavern Helper Blob URL 模式等项目相关设置；
- 控制台首个因果错误。

不能实测时，仍可交付项目包，但必须列出准确的 `not_run` 项目和用户需要手动导入、绑定、粘贴的组件。

## 新运行契约检查

- `message_surface` 允许 head + body，预览包装不改变正式制品；
- 数据型持续 UI 检查状态根、路径初始化、HTML 读取者、写入权属与回退；
- display 与 prompt-only 消费者使用同一标记；
- `compiled_frontend` 检查源码、包/锁文件、命令、输出与哈希；
- `manual/ejs_only` 世界书条目默认关闭且不使用关键词，EJS 引用必须存在；
- 0层检查整楼替换、旧楼策略、聊天切换、历史、持久化和真实生命周期脚本；
- 大型合成测试覆盖 600KB 级 HTML、模块脚本、422 条世界书与 2MB 以上角色卡 JSON 往返。
