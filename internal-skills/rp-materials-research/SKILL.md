# 原始资料整理与主动外部研究

这是 `rp-card-studio` 的材料处理模块。它处理两种独立但可以同时发生的能力：

1. `source_material_processing`：只要用户提供了任何原始资料，就整理其中与制卡有关的事实、重点、关系、规则、冲突、未知项和阶段影响。资料大小不影响是否执行。
2. `proactive_external_research`：只要项目依赖外部作品、现实事实、版本信息或改编线，默认主动使用宿主可用的公开搜索/网页读取工具查证，不要求用户额外说“可以搜索”。

## 触发规则

### 原始资料整理

以下任一情况成立就触发：

- 用户粘贴一段文字、一个章节、笔记、设定、对白或研究摘录；
- 用户提供本地文件、旧卡、世界书、脚本、网页摘录或图片参考；
- 用户要求基于某份材料创作、改写、转换、审查或制卡；
- 续接项目的 `制作文件/项目记录/materials.json` 表示存在未处理或待校准材料。

资料只有在不存在时才跳过；不能因为资料很短、只有一个文件或只有一段文字而跳过。

### 主动外部研究

以下任一情况成立就将 `research.status` 设为 `required`：

- 用户提到已有作品、IP、小说、电影、游戏、作者、历史人物、现实地点、文化背景或专业领域；
- 用户使用“同人”“二创”“沿用原作”“基于原著”“还原设定”等表达；
- 任务依赖当前版本、插件版本、宿主 API、时间敏感事实或改编差异；
- 用户材料之间的冲突需要外部来源才能判断；
- Agent 的训练记忆不足以可靠确认关键事实。
- 当前开场或持续消息前端需要新设计/方向重做，需核对真实视觉、交互、资源或当前实现参考；该研究服务当前前端阶段，不重启无关世界/角色访谈。

前端参考按其自身 opening-design/message-design 记录采用范围，既有 materials.json 中有来源时引用原材料 id，不另建来源账本。新做/重做不能只依赖训练记忆或本地设计索引；真实用户参考充分时可以直接研究，不机械凑公开来源数量。借鉴布局、组件与表现方法不等于复制作品语义，更不等于用户已确认该设计。

默认网络政策是 `public_sources_only`：只使用公开页面和当前宿主提供的搜索/网页读取能力，不绕过登录、付费墙、访问控制或地区限制，不收集私人信息，不自动下载或再分发受限正文。

用户可以明确要求“不联网”“只用我给的材料”或等价要求；此时记录 `research.status: skipped`、`research.override: user`，并把外部事实标成未查证。用户没有明确关闭时，不先反问是否允许普通公开研究。

## 原始资料整理合同

## 材料角色与参考样本边界

整理材料时必须为每份文件和每段内容标明角色：

- `authoritative_source`：用户原始卡、用户明确提供的作品源或已经确认的当前 canonical 源；用于保留和迁移语义；
- `user_confirmed`：用户在本项目中明确批准的新创作或新流程；
- `reference_only`：样本矩阵、示例卡、通用模板、外部项目和技术教程；只能支持技术可行性、宿主行为、测试方法或可选方案，不能直接决定本项目字段、页面步骤、文案和玩法语义；
- `agent_proposal`：Agent 根据材料提出但尚未获得用户确认的改造方案；不得伪装成原始事实或直接进入最终 RP-facing 制品。

旧卡改造时，原始卡的页面、字段、分组、文案和流程先做保真盘点。不要因为样本已经提供一套“主控资料矩阵”或通用 HUD，就把样本字段套入当前项目；必须先证明该字段在原始卡、本项目世界或用户决定中有来源和作用。

整理不是按字数生成摘要。每份资料至少检查并按实际适用项输出：

- 直接事实；
- 角色、地点、组织、物品、事件和关系；
- 世界规则、系统规则、行为边界和代价；
- 时间线、因果链和无人介入时的变化；
- 可进入角色卡、世界书、系统、开场、MVU/EJS 或 UI 的内容；
- 重复内容和不同表述；
- 相互矛盾的内容；
- 未证实的推断；
- 缺失信息和下一道最有价值的问题；
- 每项内容的来源文件、片段或用户原话；
- 对玩家中立、主控隔离和 `<user>` 边界的影响。

整理结果分成：

```text
核心事实
必须保留
适合角色卡
适合世界书
适合系统/状态
适合开场/UI
风格参考
冲突
未知/待确认
暂缓
```

对短文本也执行同一合同；不因为内容不足而制造无依据事实。资料较大时，只改变执行方式：

```text
短资料：一次整理并回查
中等资料：分段整理后合并
大型资料：分批整理、保留来源和续接状态
```

这只是调度策略，不是功能开关。

## 外部研究合同

研究流程是：

```text
确定研究问题和作品/版本
→ 搜索公开来源
→ 打开实际页面或使用宿主网页读取
→ 核对来源身份、版本、改编线和日期
→ 提取短事实和必要短摘录
→ 标记 canon/reference/fanon/unknown
→ 标记 confirmed/inference/uncertain
→ 记录 URL、标题、检索时间和研究范围
→ 形成制卡准备简报
```

搜索结果只是候选线索，不能直接当事实。优先官方/原作来源，再使用可靠二手资料；Wiki、社区解析和同人资料必须保留其身份。不同改编线不能混成一个标准答案。不得复制大段受限正文；只保留必要短摘录和自己的整理。

研究必须服务当前制卡问题，不自动建立百科全书。先做最小侦察：作品身份、版本/改编线、时间线、关键世界规则和当前缺口；后续阶段确实需要时再补搜。

如果宿主没有搜索或网页读取工具，必须记录 `research.status: blocked` 和缺少的能力；不得声称已经搜索、查看或核验来源。网络研究不能替代用户材料，用户明确创作决定优先于外部参考。

## 持久状态与交接

更新项目：

- `制作文件/项目记录/authority.md`：材料处理状态、研究状态、作品/版本、网络政策、当前范围和下一道门；
- `制作文件/项目记录/materials.json`：来源、提取事实、研究问题、冲突、整理结果和来源指针；
- `制作文件/项目记录/NEXT.md`：下一次从哪份资料、哪个研究问题或哪个校准事项继续；
- 当前对话进度画板：显示资料整理完成项、研究进行中、待确认、暂缓、阻断和下一道门。

保存来源和状态，不保存完整聊天记录。原始用户文件保持原样；整理文本是派生结果，不能反过来覆盖原始材料。

## 交给下游

材料阶段完成后，主 Agent 必须向定位/世界/角色阶段交付一份短简报：

1. 当前项目采用的材料和外部来源范围；
2. 已确认的核心事实；
3. 可用于制卡的条目候选；
4. 冲突、未知和未查证事实；
5. 用户仍需决定的高影响项；
6. 研究是否完成、受阻或被用户关闭；
7. 下一阶段如何消费这些结果。

`source_material_processing` 和 `proactive_external_research` 可以分别完成。没有用户资料时仍可以只做外部研究；没有外部事实依赖时仍必须整理用户资料。
