# 完整 YAML 创作源与无损世界书拆分

本项目把完整创作 YAML 视为权威源，世界书只是它的运行时分片，不是摘要版、改写版或二次创作版。

## 核心原则

```text
完整世界/角色/系统/场景 YAML
→ 校验语法与跨阶段一致性
→ 只按 YAML 子树或连续文本边界切块
→ 原文写入世界书 entry.content
→ 用 entry 的 constant/key/position/depth/order 等元数据控制激活
```

内容过长时调整**分片和调度**，不通过删句、改写、合并概念、概括或缩短来省 token。只有用户明确要求轻量版、摘要版或压缩版时，才允许从完整源派生另一个版本；完整源继续保留。

## 权威创作源

世界观、角色、系统和场景阶段使用完整中文 YAML 或用户现有等价结构，默认保留为真实创作源码，例如：

```text
世界观.yaml
角色/角色ID.yaml
系统/系统ID.yaml
场景/场景ID.yaml
```

目录和文件名可以沿用项目现状，不强迫固定结构。它们是实际 RP 内容，不是阶段账本、访谈记录或项目管理文件。

终稿 YAML 必须包含已确认的完整内容。不要为了让世界书看起来简短而先把创作源缩写成“核心规则摘要”。没有实际内容的模板空壳应删除；已经创作、确认或从材料保真的内容不得在打包时丢失。

## 无损切片

每个世界书条目的 `content` 必须来自权威 YAML 的一个连续原文片段：

- 保留原有字段名、值、列表、注释、引号、顺序和层级表达；
- 除用户明确授权外，不做同义改写、摘要、删例子、删边界、删解释或重新组织；
- 允许因 JSON 字符串编码表现为 `\n`，导入后文本必须与源片段一致；
- 切片优先位于完整 YAML mapping/list 子树边界；
- 一个子树过大时继续沿其直接子项切分，不把内容压成概述；
- 条目名称、关键词、constant、position、depth、order、概率和 EJS 调用属于调度元数据，不写进创作正文代替原文；
- 需要补充来源路径时放在条目 comment 或交付说明，不在 `content` 前后添加摘要包装。

若嵌套片段单独看缺少父路径，使用清楚的条目 comment 表示路径；不要为了补上下文而重写片段。也可以选择更高一级的完整子树，使上下文自然保留。

## 激活而不是压缩

控制上下文占用的正确手段：

- 少量总则、硬边界和当前必需规则设为 constant；
- 详细地点、势力、角色、装备、历史和系统分支用关键词；
- 秘密、条件信息和模型专用内容使用适合的 position/depth/role 或显式 EJS 调用；
- 大型列表按自然子项拆成多个原文条目；
- 当前场景只激活相关块。

不得以“模型可能看不完”为理由永久删除创作源中的内容。运行时是否激活，与交付物是否完整，是两件不同的事。

## 角色卡字段

角色卡 `description/personality/scenario` 可以按项目需要承载完整主角色 YAML、项目入口信息或必要常驻块。若同一内容已经原文进入世界书，避免无意重复激活；但去重只能通过选择单一载体，不能把两边都改成缩写。

## 允许变换的情况

只有以下情况允许改变原文，并必须回写权威 YAML 后再重新切片：

- 用户修改设定；
- QA 修复确定的事实矛盾、语法错误或字段错位；
- 目标宿主要求的必要转义；
- 用户明确要求轻量/压缩派生版。

禁止只修改世界书副本而让 YAML 源继续保持旧内容。世界书不是第二个创作权威。

## 确定性辅助脚本

仓库提供 `scripts/worldbook/split-yaml-lossless.mjs`。它按指定缩进层级识别 YAML mapping 边界，把连续原文直接写入世界书条目，并在输出前确认按 UID 顺序拼接能够逐字符重建源 YAML：

```powershell
node scripts/worldbook/split-yaml-lossless.mjs `
  --source "项目\世界观.yaml" `
  --output "项目\世界书.json" `
  --indent 0
```

如果 YAML 外层有项目根键、希望按其直接子项切片，可使用 `--indent 2`。脚本只生成保守的默认调度元数据；随后可以修改 key/constant/position/depth/order 等字段，但不得修改 `content`。含 Tab、找不到边界或无法无损重组时脚本直接失败，不会重排或重新序列化 YAML。

## 完成检查

打包前至少检查：

1. 权威 YAML 可解析；
2. 世界书每个创作条目都能定位到源 YAML 的连续原文片段；
3. 世界、角色、系统、场景的所有已确认块都已进入目标载体，或明确说明为何只保留在角色卡字段；
4. 将同一源文件对应的条目按源顺序拼接后，与源文件正文一致；
5. 不存在只在压缩摘要里出现、却在完整源中找不到的新增事实；
6. 不存在完整源有内容、世界书打包时静默遗漏的块；
7. 内容哈希与交付制品绑定；没有无损检查证据时，不声称“完整保真拆分”。
