# 开场介绍与路线前端

这个前端只服务正式 RP 之前的一次性进入流程。它将已经确定的项目介绍、玩法说明、路线选择和开场映射变成可操作页面，不重新创作叙事内容。

## 输入合同

从叙事与开场阶段取得：

- 项目标题、核心体验和必要游玩说明；
- 可选路线及其可理解的差异与影响；
- 默认开场和备用开场的实际标识；
- 玩家在提交前必须知道的限制、风险和远程依赖；
- 无前端或前端失败时使用的短文本回退。

没有这些内容时返回 `narrative_opening` 补齐，不在页面实现中临时发明路线语义。

## 页面旅程

推荐顺序：

```text
简短项目入口
→ 路线/开场选择（如需要）
→ 创角或开局配置（如需要）
→ 汇总预览
→ 明确确认
→ 真实提交与读回
→ 进入选择的开场
```

不是每个项目都需要所有页面。轻型项目可以在一个完整 HTML 中完成，不为了步骤感拆页。

## 路线选择

- 默认不替玩家选择路线；确有唯一推荐入口时可以突出推荐，但仍由玩家主动确认；
- 每条路线说明玩家能观察到的体验差异，不用内部 ID、变量字段或实现术语解释；
- 选择结果必须映射到真实 greeting、开场标识或初态覆盖；
- 路线不可用时显示原因和回退，不静默跳到另一条路线；
- 多次点击或重复提交不能创建重复状态、重复消息或重复初始化。

## 载体

开场页面可以由 Tavern Helper fenced HTML、ST-Prompt-Template `@@iframe` 或其他已验证宿主建立。纯 SillyTavern 只承诺静态介绍内容，不能声称其中 JavaScript 会执行；需要路线提交、创角写入或 greeting 跳转时必须选择真实可交互载体，不能用静态按钮伪装成功。

完整 `.html` 是维护和交付源码；运行时还必须有真实 provider、marker/条目和必要正则。远程资源失败时仍要保留可读文字和进入游戏的回退路径。

## 建议式访谈

重点问玩家进入正式游戏前必须理解什么、路线差异是否值得在开局前暴露、以及页面应该多快让人进入 RP。每个问题先给推荐信息层级和交互路径，说明为什么它符合核心体验，并指出会怎样影响首屏长度、创角负担和开场映射。

标准模式至少用窄屏、无路线选择和路线不可用中的一个情境校准最终 HTML。
