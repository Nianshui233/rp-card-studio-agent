# 开场介绍与路线前端

这个前端只服务正式 RP 之前的一次性进入流程。它将已经确定的项目介绍、玩法说明、路线选择和创角字段变成可操作页面，不重新创作叙事内容，也不在运行时修改世界书。

## 输入合同

从叙事与开场阶段取得：

- 项目标题、核心体验和必要游玩说明；
- 可选路线及其可观察差异与影响；
- 每条路线对应的真实静态 Greeting/Swipe 可见名称；
- canonical 玩家开局登记文本的字段和 marker；
- 玩家在发送前必须知道的限制、风险和依赖；
- 无前端或剪贴板失败时使用的纯文本回退。

没有这些内容时返回 `narrative_opening` 补齐，不在页面实现中临时发明路线语义。

## 页面旅程

推荐顺序：

```text
简短项目入口
→ 路线/开场选择
→ 创角或开局配置
→ 汇总预览
→ 生成完整登记文本
→ 复制或手动复制
→ 告知目标 Greeting 与粘贴发送步骤
→ 玩家亲手发送第一条消息
→ 退出开场页面职责
```

不是每个项目都需要多页。轻型项目可以在一个完整 HTML 中完成，不为了步骤感拆页。

## 路线选择

- 默认不替玩家选择路线；确有唯一推荐入口时可突出推荐，但仍由玩家主动确认；
- 每条路线说明玩家能观察到的体验差异，不用内部 ID、变量字段或 API 术语；
- 每条路线都必须映射到真实、可手动选择的静态 Greeting；
- 自定义来意使用静态自由入口 Greeting，不在运行时重写第 0 楼；
- 路线不可用时显示原因和修复建议，不静默跳到另一条路线；
- 页面重复挂载或多次复制不会创建状态、消息或初始化副作用。

## 载体

开场页面可以由 Tavern Helper fenced HTML、ST-Prompt-Template `@@iframe` 或其他已验证宿主建立。纯 SillyTavern 只承诺静态介绍内容，不能声称其中 JavaScript 会执行。

因为开场页只生成和复制文本，它不需要获得世界书、聊天写入或 TH 高权限 API。即使运行在同源 iframe，也把权限面保持最小：

- 不访问 `window.parent` 的世界书与聊天写 API；
- 不修改输入框；
- 不自动发送；
- 不切 Swipe；
- 不读取持续消息状态。

完整 `.html` 是维护源码；运行时还需有真实 marker 与显示正则。远程资源失败时保留可读文字、完整文本和手动开场路径。

## 草稿与预览

页面草稿可以只存在内存；若要跨刷新保存，使用按聊天/角色隔离的本地草稿并明确告知。无论是否保存：

- 修改任一字段后，旧预览和旧复制状态立即失效；
- 复制按钮始终复制当前可见全文；
- 页面不把复制状态持久化成“已开场”；
- 切换聊天不会让旧草稿自动发往新聊天。

## 个性化设计访谈（实现前必经）

开场页的视觉气质与玩家进入作品的第一印象属于核心创作决定，优先于实现细节。除非用户已经给出充分设计简报或明确授权自由设计，否则在动手写视觉 HTML 前，逐项确认：

1. **视觉方向**：玩家进入时应感到什么；喜欢/不喜欢什么参考风格或作品。
2. **展示内容**：开局前必须知道什么，哪些信息不该剧透。
3. **排版与节奏**：首屏先呈现氛围还是直接选择；简洁、章节化、卡片化或叙事化。
4. **交互感受**：一页还是分步；预览、返回修改、复制成功、复制失败和操作指引怎样呈现。

访谈要把偏好变成具体设计，不以“通常更易用”为由覆盖用户主题。不要问 CSS token、框架、API、iframe 或剪贴板实现；这些由 Agent 负责。

标准模式至少用窄屏、缺失路线、剪贴板拒绝、修改后旧预览失效中的一个情境校准最终 HTML。
