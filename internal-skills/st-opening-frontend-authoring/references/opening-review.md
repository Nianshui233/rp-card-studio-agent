# 开场与创角：从实际画面复核

这是一遍面向入场体验的复核，不套用状态栏的密度、刷新或长期操作规则。制作完成后暂时离开实现者视角，从实际截图与操作重新检查；没有另一模型参与时，不声称独立模型审查。

## 看什么，怎样判定

| 观察对象 | 需要回答的具体问题 | 对应证据 |
|---|---|---|
| 世界呈现 | 首屏是否出现值得进入的具体世界内容？主次为何这样安排？图像、空间或文字表达是否匹配本作？ | 当前宽屏、窄屏首屏，以及实际图像或图形。 |
| 阅读路线 | 长介绍能否定位章节、回查内容、随时找到入口？ | 真实滚动、导航、展开后的状态。 |
| 指南 | 能否理解可以做什么、什么仍未知？作品约定与工程说明是否分离？ | 规则首层、按需细则和例子。 |
| 创角 | 字段是否源于本作？分支、返回、可空、预设、修改和结果是否来自同一草稿？ | 实际填写、返回、修改和结果预览。 |
| 视觉执行 | 中文层级、图形、颜色与构图是否相互配合，而非文字套壳？ | 最长标题、真实长选项、字体与素材成功加载后的画面。 |
| 交接出口 | 玩家是否知道结果只是草稿、复制资料还是实际登记？ | 成功、取消、失败和恢复操作；不得以按钮文案证明写入。 |

不用“用了地图/动画/很多代码”证明好看；纯文字可以成立，但需要真正的排版与入场节奏。没有使用的模块说明不适用，不强行补齐。

## 有问题怎样写

只记录当前仍需解决的问题或当前方案的复核结论，不建立失败故事库。每个问题说清：可检验的问题、具体截图区域或节点、对认识世界/创角的影响、准备怎样改变、在哪个尺寸/状态复测。无对应证据时标待核对，不以个人喜好定罪。

如果问题是整体表达失效，重新组织构图、导航或创角方式；不靠印章、纹理和阴影堆叠回答。保留已确认的世界事实与功能，是否改变已选方向仍走原有决定来源。

复核写回现有 `frontends.opening_frontend.designReview` 的 worldPresentation、guideComprehension、creationFlow、visualExecution；引用当前导入内容与实际 caseIds。工具只能检查证据一致，审美仍须看实际画面。打磨中的临时覆盖截图不能计为正式设计复核。
