# 创角、剪贴板交接与手动开场

创角前端只收集正式开局确实需要的玩家资料与初始选择。它不为完整感要求玩家在不了解世界时填写整套履历，也不预填最终玩家人物。

## 字段分工

```text
页面草稿
→ 只存在于当前开场页面；用于编辑与预览

canonical 开局登记文本
→ 玩家可见、可编辑、可复制的唯一交接载体

玩家长期状态
→ 玩家发送登记文本后，由首轮 MVU/项目运行合同写入

世界书
→ 交付时预制的静态规则与内容；开场页运行时不修改
```

同一事实只能有一个运行权威。页面展示的是待发送草稿；只有真实进入聊天历史的玩家消息及其后生成的持久状态，才算已经登记。

## 表单规则

- 正式字段默认空白；placeholder 只能举例，不能成为提交值；
- 快速预设默认不选，玩家主动选择后仍可逐项编辑；
- 只要求会改变开场、长期称呼、权限或运行初态的字段；
- 可留到 RP 中自然形成的资料明确标记可选或“未设定”；
- 不读取或猜测制作用户本人的身份作为玩家默认值；
- 校验错误贴近字段显示，并保留其他已填内容；
- 预览和复制必须来自同一个 `buildOpeningMessage(draft)`；修改任何字段后立即使旧预览失效。

## canonical 开局登记文本

建议使用显眼且项目唯一的纯文本 marker：

```text
【项目名·开局登记】
玩家称呼：……
公开来历：……
公开专长：……
行事倾向：……
选择路线：……
本次来意：……

请承接当前 Greeting 正常开场，并把以上公开资料登记到本聊天状态。
除这些公开资料外，不替我补写过去、想法、台词或下一步行动。
```

要求：

- 所有字段都能被玩家直接阅读和修改；
- 不含世界书 UID、消息 ID、Swipe 索引、JSON 转义或宿主 API 术语；
- marker 和字段名与首轮运行合同完全一致；
- 内容足以让模型完成首次登记，但不把整套世界设定重复塞进消息；
- 后续更正使用另一个明确 marker，例如 `【项目名·更正开局登记】`，并只修改玩家指定字段。

## 路线与 Greeting

所有路线都走同一种可靠交接：

```text
选择路线
→ 生成登记文本
→ 告诉玩家应切换到哪个真实 Greeting
→ 玩家手动切换第 0 楼 Swipe
→ 玩家粘贴登记文本
→ 玩家亲手发送
```

固定路线使用现有剧情 Greeting。自定义路线也必须提供一个静态自由入口 Greeting，由它询问来意并承接登记文本；禁止依赖脚本在提交时重写第 0 楼。

指引使用 Greeting 的可见标题或首句描述，不只写“Swipe 2”。如果目标 Greeting 缺失，页面要停止生成最终指引并明确提示制作者修包，而不是静默选择别的路线。

## 剪贴板与回退

复制按钮必须由真实用户点击触发：

1. 首选 `navigator.clipboard.writeText`；
2. 失败时把完整文本放进可见、只读、可选中的 `textarea`，尝试 `document.execCommand('copy')`；
3. 仍失败时保持全文选中，明确提示 `Ctrl+C` / 长按复制；
4. “复制成功”只表示剪贴板已取得文本，不表示已粘贴、已发送或已登记。

页面必须始终让玩家看到将要复制的全文。不能只有一个“完成”按钮而没有可核对输出。

## 首轮登记合同

首轮 AI 回复的更新规则负责把真实玩家消息转成持久状态：

```text
系统.开场状态 != 已登记
+ 当前 user 消息以项目开局登记 marker 开头
→ 精确读取允许字段
→ 在同一 UpdateVariable 中写入玩家字段、路线和 开场状态=已登记
→ 自定义路线按本次来意同步任务名称/阶段
→ 正常继续当前 Greeting 的剧情
```

登记完成后：

- 不从普通叙事、称呼变化或模型猜测改写玩家档案；
- 只有明确的更正 marker 才修改指定字段；
- 缺失字段保持原值或未知，不自行补齐；
- 首轮更新失败时保留玩家原消息，让用户重新生成 AI 回复；不要建议去世界书里补写。

## 玩家操作指引

最终页面至少明确写出：

1. 手动切换到哪个 Greeting；
2. 回到 SillyTavern 消息输入框；
3. 粘贴完整登记文本；
4. 确认它是新聊天的第一条玩家消息；
5. 亲手点击发送；
6. 等待 AI 回复与状态栏；
7. 检查玩家称呼、路线和开场状态是否已登记。

如果输入框已有其他草稿，页面不覆盖它；让玩家先保存草稿或自行决定合并。开场页不需要读取输入框内容才能工作。

## 禁止的实现

禁止为了“更自动”而恢复以下路径：

- 创建、更新、删除或启用 `<user>` 世界书条目；
- 用世界书读回判断创角成功；
- 自动切换 Swipe 或改写第 0 楼；
- `/send ... | /trigger` 自动发送；
- `createChatMessages` 插入 user 楼；
- 直接写 MVU 后宣称玩家已经完成开场；
- 把复制成功误写成提交成功。

## QA

至少覆盖：

- 三条路线都生成正确、不同的 Greeting 指引；
- 自定义来意不足时不能生成；
- 修改字段后旧文本不能继续复制；
- Clipboard API 不可用时仍可手动复制；
- 输出正文不含未授权默认值；
- 打包后的 HTML 与维护源一致；
- 协调脚本中无世界书写入、自动发言和 Swipe 修改；
- 世界书规则能从真实首条玩家消息完成首次登记；
- 重新生成 AI 首回复不会重复插入物品或线索等非幂等副作用。
