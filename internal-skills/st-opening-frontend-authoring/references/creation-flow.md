# 主控资料、复制交接与手动维护

创角前端只收集用户愿意用于当前游玩的主控资料。它不为完整感要求玩家填写整套履历，不把制作用户当成角色，也不把某一份资料写成世界核心事实。

## 内容归属

```text
页面草稿
→ 只存在当前页面，用于编辑与预览

用户主控资料
→ 用户看得见、改得动、可复制并自己维护/导入的资料

固定主控预设
→ 可选的独立剧情入口，关闭后不影响开放世界核心

世界核心
→ 世界、NPC、固定角色、规则和场景；不依赖单一主控

持久运行状态
→ 只有在用户选定 MVU 后，按已确认运行合同保存；不由前端偷偷创建
```

同一事实只能有一个权威。页面不是世界书，世界核心不是玩家资料，NPC 本体也不是当前主控与它的私人关系。

## 主控资料规则

- 正式字段默认空白；placeholder 只能举例；
- 预设默认不选，玩家主动选择后仍可查看和修改；
- 只要求会改变当前入口或用户明确希望长期保留的资料；
- 可以留到 RP 中自然形成的内容标记为“未设定”；
- 不读取或猜测制作用户本人的身份作为主控默认值；
- 不把“与某 NPC 的关系”默认为朋友、仇人、恋人或旧识；若用户填写，关系属于当前主控资料/当前情境，不改写 NPC 本体；
- 用户可以准备多个主控资料；每次只说明哪一份被用户选为当前活动主控，不自动合并；
- 校验错误贴近字段显示并保留其他内容；
- 预览和复制来自同一个 `buildPlayerProfile(draft)`；修改任意字段后立即使旧预览失效。

## 可复制的主控资料块

建议使用显眼且项目唯一的纯文本 marker，并把内容设计成用户可以直接粘贴到自己维护的 `<user>`/主控条目中：

```text
【项目名·主控资料】
资料名称：……
主控称呼：……
公开来历：……
公开专长：……
行事倾向：……
与已知人物的关系（可不填）：……
本次进入方式/来意（可不填）：……

以上只代表本份主控资料，不改变世界核心、NPC 基础设定或其他主控资料。
未填写内容保持未设定；请不要替我补写过去、关系、台词或下一步行动。
```

要求：

- 所有字段都能被用户直接阅读和修改；
- 不含世界书 UID、消息 ID、Swipe 索引、JSON 转义或宿主 API 术语；
- marker、字段名与用户维护/导入说明和运行合同一致；
- 不把整套世界设定重复塞进主控资料；
- 后续更正使用另一个明确 marker，例如 `【项目名·主控资料更正】`，只修改用户指定的当前主控字段；
- 复制出的文本默认是“待用户维护/导入”，不是“已登记”“已发送”或“已写入”。

如果项目没有 MVU，仍然可以生成供用户维护的资料块，但不得宣称它会自动跨消息保存；如果启用了 MVU，资料首次导入/维护后的读取与保存由独立运行合同负责，而不是由开场页面直写。

## 交接路线

默认路线是用户自己维护或导入，不是把资料发给 AI：

```text
选择开放世界/固定预设/自定义主控
→ 生成资料块
→ 用户复制或手工复制
→ 用户打开目标独立世界书或用户资料文件
→ 用户把资料粘贴到自己的 <user>/主控条目，或导入交付文件
→ 用户保存并确认当前启用的主控
→ 用户手动选择真实 Greeting/Swipe
→ 新建或继续聊天开始游玩
```

开场页不应把资料自动放入聊天输入框，更不应要求用户将资料作为第一条 user 消息发送。若项目另有独立、用户明确启用的 Tavern Helper 资料维护工具，可以代替“手动粘贴”这一步，但必须：

- 明确显示目标条目；
- 要求用户确认；
- 支持重复执行不产生重复条目或重复字段；
- 失败时保留原内容并给出手工路径；
- 不自动发送聊天、不自动切 Greeting、不把结果当作剧情已登记。

Greeting 只负责承接已经由用户维护/导入的主控（或无主控的开放入口）。如果目标 Greeting 缺失，停止生成最终指引并报告修包，不静默选择其他路线。

## 复制与回退

复制按钮必须由真实用户点击触发：

1. 首选 `navigator.clipboard.writeText`；
2. 失败时把完整资料放进可见、只读、可选中的 `textarea`，尝试 `document.execCommand('copy')`；
3. 仍失败时保持全文选中，明确提示 `Ctrl+C` / 长按复制；
4. “复制成功”只表示剪贴板已取得文本，不表示已粘贴、已维护、已导入、已启用或已开始游玩。

页面必须始终让用户看到将要复制的全文。不能只有“完成”按钮而没有可核对资料。

## 当前活动主控与无主控状态

状态栏或其他消息前端只能读取用户已经维护/导入且被宿主标记为当前活动的主控资料。它不得根据称呼、叙事或 NPC 反应猜测当前主控。

- 有当前活动主控：显示该主控资料及其当前状态；
- 没有主控：显示世界状态，主控区域写“未登记/未选择”，不伪造身份；
- 有多份但没有明确活动项：显示“未选择当前主控”，不合并关系；
- 切换主控：重新读取目标资料，旧主控的个人状态、物品、知识和关系不带入新主控；
- 主控资料里的私人关系只影响当前主控情境，不改写 NPC 基础条目。

## 禁止

禁止为了“更自动”而恢复以下路径：

- 开场页面创建、更新、删除或启用 `<user>` 世界书条目；
- 把用户主控资料直接发送给 AI 作为默认登记方式；
- 自动切换 Swipe、改写第 0 楼或插入 user 楼；
- `/send ... | /trigger` 自动发送；
- `createChatMessages` 插入主控资料消息；
- 直接写 MVU 后宣称用户已经完成主控导入；
- 把复制成功误写成资料已保存或剧情已开始；
- 把某一主控的关系、物品、经历写回世界核心或其他主控。

## QA

至少覆盖：

- 开放世界、固定预设、自定义主控的指引互不混淆；
- 无主控时也能进入世界，且不编造单一玩家；
- 主控 A/主控 B 切换后 NPC 关系、物品、知识和状态不互相污染；
- 自定义资料允许未设定字段，不静默补全；
- 修改字段后旧文本不能继续复制；
- Clipboard API 不可用时仍可手动复制；
- 输出正文不含未授权默认身份；
- 开场页面和协调脚本无聊天写入、自动发言、自动 Swipe 或静默世界书写入；
- 若存在独立资料维护助手，目标条目、确认、幂等、回滚和手工回退可验证；
- 打包后的 HTML 与维护源一致，marker 与实际正则一致。
