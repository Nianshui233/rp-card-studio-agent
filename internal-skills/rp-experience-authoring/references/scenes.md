# 场景阶段（可选）

场景是可进入、可感知、可行动、会变化的 RP 空间。它可以作为完整世界书条目保存，不必拆成数据库式坐标；但空间关系、权限、线索和行动后果必须清楚到足以支持真实游玩，而不是只写一张氛围图片。

## 先判断场景需要多深

根据玩法选择深度，不按模板完整度堆内容：

- **日常/会面/关系型**：重点是生活节奏、感官、人物使用方式、私密与公开区域、能自然发生的互动。
- **探索/经营/长期据点型**：增加区域功能、资源流、维护变化、人员日程、扩建与破坏后果。
- **潜入/推理/战术/密室型**：完整处理拓扑、入口、门禁、视线、巡逻、警报、线索分布、时间窗口、备用路线和失败后果。
- **超自然/规则型**：除空间事实外，明确局部规则、异常征兆、触发条件、边界案例和无法通过普通手段解决的限制。

复杂度由场景承担的玩法决定。普通卧室不需要伪造十二个区域；一座反复潜入的设施不能只写“入口、仓库和秘密”。

## 允许讨论

- 场景承担什么体验、平时如何运转，在哪些时段呈现不同面貌；
- 外观、气味、声音、拥挤度、天气、照明、材质和情绪；
- 总体规模、区域层级、空间拓扑、主辅通道和不可即兴改变的空间事实；
- 常驻人物、来往人群、日程、轮班、生态和场外变化；
- 入口出口、门禁、权限获取、监控、巡逻、警报、规避路线和失败后果；
- 可互动、可获取、可破坏、可改造的事物及其连锁后果；
- 线索所在位置、获取方式、前置条件、时间窗口、误导和能推出什么；
- 表层可见信息、深入观察、条件信息、谣言和 GM/秘密信息；
- 随机事件、必然事件和势力行动怎样改变场景并留下长期痕迹；
- 无图片、音频或 UI 时如何仅靠文本成立。

不重新设计人物人格、世界底层规则、变量实现、开场文风或 UI。需要人物、系统或世界事实改变时返回交接。

## 分轮工作方式

### 第一轮：用途、尺度与日常

询问场景类型、反复承担的玩法、总体规模、危险度、开放程度，以及正常状态下谁在这里做什么。先让场景作为真实地点成立。

### 第二轮：空间与行动

确定入口、区域、连通关系、视线、移动耗时、权限和限制。对结构型场景，用自然中文写清拓扑，例如：

```text
正门 → 接待厅 → 中央走廊
中央走廊 → 档案区 / 办公区 / 维修梯
维修梯 → 地下机房 → 退潮涵洞
```

不需要绘制精确地图，但不能让门、楼层和邻接关系随剧情方便任意改变。

### 第三轮：人物、资源、线索与压力

补充常驻者和流动人群、资源、物品、可破坏点、警戒系统与线索结构。线索不是“这里有证据”，而应写明在哪里、怎样获得、会不会误导、能支持什么结论。

### 第四轮：时间、事件与长期变化

确定白天/夜晚、换班、潮汐、天气、营业、宵禁等时间差异；写出无人介入时仍会发生的事件、势力下一步，以及事件后场景留下的持续变化。

### 第五轮：行动压力测试（按需）

根据场景用途挑选真实行动演算：进入、离开、潜入、追逐、搜索、交易、谈判、战斗、破坏、救援、藏匿、休息或长期经营。检查每种关键行动是否有路径、阻力、反馈和失败后果。

## 推荐源码

新建场景使用 `assets/templates/scene.yaml`。不适用的模块可以删除；对承重玩法不能因为字段较多而压成几句概述。

一个结构型场景的关键片段可以是：

```yaml
display_name: "旧检疫码头"
purpose: "调查、黑市交易与势力冲突的交汇场所"
play_focus: [调查, 潜入, 交易, 逃脱]

daily_life: |-
  白天由港务处封锁并进行例行消杀；换班后的两小时由搬运工、走私客和无证医生分段占用。
  配给、巡检和潮位不会因当前视角离开而暂停。

spatial_structure:
  scale: "沿岸四座仓房、旧铁轨与一段退潮涵洞"
  topology:
    - "港务处正门 → 消杀院 → 登记室 / 封存仓"
    - "封存仓 → 维修夹道 → 退潮涵洞"
  immutable_facts:
    - "封存仓只有正门和维修夹道两个可供成年人通过的出口"
  zones:
    - id: sealed_warehouse
      name: "封存仓"
      function: "保存未完成登记的货物与检疫样本"
      visible_information: ["货架编号被重新刷过", "北墙有新鲜水痕"]
      interactions: [翻查登记, 观察交接, 拆开夹层]
      risks: ["停留过久会同时引起巡检与仓内异变注意"]
      connects_to: [disinfection_yard, maintenance_passage]

access_and_security:
  entrances:
    - name: "港务处正门"
      requirements: [通行证, 熟人带领]
      failure_consequence: "身份被登记并提高本夜巡逻警觉"
  surveillance: ["登记室能看见正门和消杀院，但看不到维修夹道"]
  patrols: ["换班前每二十分钟一次，换班后存在四十分钟空窗"]
  alarm_triggers: ["破坏封条", "同一证件重复进入"]
  bypasses: ["利用退潮涵洞", "伪造一次性搬运单"]

clue_structure:
  - clue: "被删去的乘客批次"
    location_ref: scene:old_quarantine_dock/zone:sealed_warehouse
    acquisition: "对照货架底层的旧铅笔编号与登记册"
    prerequisites: ["能进入封存仓", "至少检查两组编号"]
    time_window: "下一次消杀前"
    possible_misdirection: "看起来像普通走私批次"
    supports: "有人系统性删改从未下船的乘客记录"

time_and_events:
  time_variations:
    - period: "换班后两小时"
      changes: ["正门审查放松", "走私团接管维修夹道"]
  offscreen_events:
    - trigger: "走私团连续两夜没有取得燃料"
      event: "交易转为抢夺民用仓库"
      visible_aftermath: "南岸出现烧毁的手推车和临时封锁"
```

## 场景质量审计

锁定前检查：

- **空间闭环**：所有承重区域都有入口或连通来源，不存在凭空抵达或无理由消失的出口；
- **权限闭环**：限制有获取、绕过、失败和后果，不只是“这里不能进”；
- **线索闭环**：重要结论至少有可执行的获取路线；线索位置、获取方式和推论相互匹配；
- **时间闭环**：换班、天气、潮汐或营业变化会真实改变行动，而不是装饰文字；
- **资源闭环**：可获取或可破坏对象有用途、限制和后果；
- **行动闭环**：场景的核心玩法有可行路径、阻力、反馈与失败结果；
- **自主运行**：人物、生态、巡逻、交易和势力事件在镜头外仍继续；
- **信息分层**：表层可见、调查所得、谣言和 GM 秘密没有混写；
- **世界一致性**：局部规则、治安、技术和资源没有越过上游世界硬设定。

## 完成门槛

- 场景不只是背景图片，而有日常、行动、变化和可持续后果；
- 深度与玩法相称，轻场景不臃肿，结构型场景不空洞；
- 承重区域、入口、拓扑、限制、风险和可继续推进的方向可判定；
- 线索、权限、时间窗口和可破坏结构在需要时形成闭环；
- NPC/势力不因当前视角离开就停止行动；
- 可整体放入世界书，不依赖尚未实现的 UI 才能理解。
