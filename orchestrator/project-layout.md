# 作品目录与两包交付

本合同管理作品项目，不重排 Agent 工具包仓库。作品最外层从制作开始就只有两个实际文件夹：导入包、制作文件；根目录不散落 README、清单、源码或隐藏账本。各宿主使用同一布局，不依赖 Codex 独有目录。

```text
项目名/
├─ 导入包/
│  ├─ 项目名.角色卡.json
│  ├─ 项目名.世界书.json
│  ├─ 项目名.正则.json
│  ├─ 项目名.酒馆助手脚本.json
│  └─ 导入说明.txt
└─ 制作文件/
   ├─ 创作源/        # 完整 RP 原稿，按实际内容组织
   ├─ 原始资料/      # 用户材料；不是旧成品备用路线
   ├─ 运行源码/      # HTML、JS、Schema、EJS 等制作源码
   ├─ 配置/          # 实际运行合同和生成设置
   ├─ 构建/          # 当前编译结果；不保存上一版/另一路线
   ├─ 检查/          # 有用的用例和直接证据，不留临时垃圾
   └─ 项目记录/      # 续接、授权、来源、验收与当前清单
```

示意文件不要求全部存在。未启用功能不生成空组件；制作文件内只建立实际需要的子目录。角色卡采用本次选定格式，不默认同时提供可替代的 JSON/PNG 版本。导入包默认平铺，不再创建角色卡/世界书/正则/酒馆助手脚本/原始HTML分类层。

## 归属

- 导入包只放真正导入/直接使用的成品，以及唯一简短的导入说明.txt。源码、配置、账本、机器清单、检查结果、解释指南、截图和测试样例归制作文件。
- 原始 HTML 归运行源码；酒馆需要的界面内容先完整构建到实际使用的脚本/正则等载体中。不让用户到制作目录复制代码、补文件或拼页面。
- 必需的独立运行资源可以例外声明为 runtime_asset，并指定实际引用它的成品；资源必须包含在包内，不能把源码换个标签冒充资源。依赖外部扩展/远程 provider 的要求在导入说明写清，制作文件不能成为运行依赖。
- 机器交付清单固定为制作文件/项目记录/交付清单.json，只描述当前单一路线。清单不是给用户导入的组件，不进入导入包。
- 项目记录仍使用 authority.md、NEXT.md、materials.json、acceptance.json、production.json、route-lock.json 等既定格式，统一位于制作文件/项目记录；目录整理不增加或变造用户确认。
- 当前原稿只有一份权威，交付成品由其生成。需要修正时先修改权威原稿再重建，不在多个位置维护互不相同的副本。

## 清理与旧项目

制作文件不是旧版、修复版、失败历史或备用路线的堆放处。只保留原始输入、当前制作资料和必要证据；清理无用临时文件，不建立 history/backup/superseded 路线。原始卡作为原始材料保留，不当作第二个可导入候选。

旧项目需先盘点当前成品与权威原稿，规划实际移动和引用更新；发现目标冲突就停止，不覆盖或删除用户材料。移动授权记录不改变账本事实、审阅状态或授权范围。工具发现旧位置账本或根目录散落内容时会阻断新初始化，不能悄悄另起一套记录。迁移后重新生成并检查路径/哈希，不能继承旧运行声明冒充新版验收。

## 执行检查

```text
node scripts/delivery/deliverable-check.mjs layout --root <作品项目目录>
node scripts/delivery/deliverable-check.mjs layout --root <作品项目目录> --final
```

制作阶段检查顶层两文件夹和导入包卫生；最终检查追加当前机器清单、文件成员和唯一导入说明。单独复制导入包后还要做包级/实际宿主检查；目录整齐不能替代运行验收。最终报告先给导入包与制作文件两个绝对路径及简短用途，不把所有中间文件逐一甩给用户。
