# 作品来源、参考样本与制品纯度合同

本文件是主 Agent 和各阶段 Skill 共用的边界合同。它解决两种不同污染：

1. **实现污染**：把世界书、条目、MVU、脚本、正则、Prompt、前端载体或构建过程写进 RP 内容；
2. **参考样本污染**：把样本矩阵或其他参考项目的字段、步骤、页面语义和文案直接套进当前项目。

## 来源优先级

对世界、角色、系统、场景、开场和主控前端，来源优先级固定为：

```text
用户明确的新决定 / 新创作
> 用户提供的原始卡或原始作品材料
> 当前项目已确认的 canonical 源
> 仅供参考的样本、矩阵、示例卡和通用模板
> Agent 自己的推测或惯用结构
```

原始卡是**语义金标准**。改造旧卡时，先从原始卡提取保留、迁移、重写、删除和待确认项；不能因为它是单文件、旧格式或没有新技术组件，就用样本项目的结构替换它。

参考样本默认只有 `reference_only` 身份：可以参考技术可行性、宿主 API、生命周期和测试方式，不能直接决定当前项目的字段、页面步骤、文案、视觉媒介、状态根、角色关系或玩法语义。任何从样本得到的新增内容，都必须先作为 Agent 提案展示并取得用户确认，不能因为“样本已经这样做过”就直接落盘。

## 作品层、运行层、维护层

每项新增文本、字段和文件先标明所属层：

- **作品层**：世界观、角色、系统、场景、叙事规则、开场事实和玩家边界；必须能脱离具体宿主独立成立。
- **运行层**：状态协议、解析格式、载体适配、必要隐藏 marker、Schema 和脚本；只放在实际需要运行它的合同或代码中，不回流进作品层。
- **维护层**：世界书/条目/UID 组织、构建说明、导入步骤、测试日志、阶段账本和 Agent 续接信息；不进入最终 RP Prompt、角色卡作品内容或玩家可见页面。

作品层可以保留原始卡中已有的“AI 角色扮演”“硬设定优先”“本文档用途”等原文；不能用简单禁词表误伤原始内容。污染判断看**来源、语义和所属层**，不是看某个词是否出现。

如果运行能力必须通过宿主 Prompt 传递，运行合同也只能写最小、宿主中立、不可见于玩家的协议，不得解释“世界书第几条”“读取哪个工程文件”或“Agent 如何构建制品”。

## 新增内容来源闭合

进入 RP-facing 文件的每个新增段落、字段、页面步骤和玩家可见文案，必须能归入以下一种来源：

```text
original_card      原始卡原文或其无损拆分
user_confirmed     用户明确批准的新内容
canonical_source   已确认的当前项目创作源
runtime_required   必要且隔离的运行协议
```

`reference_only` 和 `agent_proposal` 不能直接进入最终制品。无法说明来源的新增内容保持 `unresolved`，在来源闭合前阻断交付，不把“看起来合理”当作来源。

## 前端专用合同

开场/创角前端不是通用表单生成器，持续消息前端也不是样本 HUD 的复制品：

1. 先盘点原始卡已有的入口、字段、分组、语义和玩家流程，再决定保留、迁移、重写或删除；
2. 样本矩阵只提供技术参考，不得作为本项目字段和步骤的权威；
3. 每个新增字段说明它服务于本项目哪个世界事实、玩法后果或已确认体验；没有对应语义就不添加；
4. 用户未明确声明的主控姓名、身份、关系、目标、决定和承诺不得被表单默认值或剧情推测填入；
5. 页面只能消费真实状态或用户主动填写的资料，不创建影子状态、假数据或默认玩家；
6. 前端读取器只依赖实际需要的状态载荷。`stat_data` 是前端渲染所需的状态载荷；如果 provider 同时提供 `schema`，它可以是对象或字符串，不能因为 `schema` 不是对象就拒绝有效状态。完整 MvuData/桥接校验仍按对应 provider 合同判断是否存在必要字段；
7. 真实状态缺失、空态、旧楼层、Swipe、编辑、宿主未初始化和错误载荷都必须有可逆、玩家可理解的回退，不把内部 API、文件名或调试堆栈展示给玩家；
8. fenced HTML/iframe 的 `html/body` 是宿主消息里的画布，不是独立网页背景：默认使用透明根背景，让宿主消息背景透出；如果确实需要不透明底色，必须把它作为明确的全幅 surface 设计，而不是让 `body` 的黑色背景形成意外边框；
9. 不把宿主背景、iframe 画布、内容容器的留白混称为 CSS border。前端 QA 必须在带有宿主背景的模拟父容器中检查宽屏、窄屏、内容较短、内容较长和滚动边缘，确认没有意外黑边、黑色画布或高度错觉；
10. 交付前至少用真实导出的状态快照覆盖：正常状态、`schema` 为字符串、无 `schema`、空状态、部分状态、无状态楼层、切 Swipe 和消息重载。

## 交付前门禁

QA 与交付必须分别完成：

- **来源审计**：相对原始卡和已确认 canonical 源解释每项新增内容；
- **层级审计**：维护说明没有回流进作品层，运行协议没有伪装成世界观；
- **参考审计**：样本只留下技术借鉴证据，没有未经批准的字段/文案/流程复制；
- **前端回归**：真实快照载荷可以被读取，页面不会因无关字段类型失败；
- **状态来源审计**：更新块中的用户状态、目标、关系和数值都有用户原话、材料事实或本轮可指认叙事事实，Agent 推测不得直接落库。

“静态文件通过”“样本看起来能运行”不能替代这些门禁，也不能被写成用户接受或真实宿主验收。

## 单一路线与作品层污染扫描

最终交付包必须有一个 `active-route` manifest，声明唯一 active route、当前组件文件和 superseded 路线。旧路线只能放在 `.internal/history/`，不能继续出现在用户可导入目录，也不能与 active route 并列作为候选。

使用：

```text
node scripts/delivery/deliverable-check.mjs active-route --manifest <delivery-root>/manifest.json --root <delivery-root>
node scripts/delivery/deliverable-check.mjs purity <RP-facing-file>...
```

`purity` 只扫描被明确标记为 RP-facing 的文件；运行层和维护层文件不通过禁词猜测来审查，必须在 manifest 中分层。作品层发现本机路径、`runtime: not_run`、工程导入指令、Agent/Skill/账本/交接语义时阻断交付；原始卡原文仍以来源和层级合同为准，不进行机械误伤。
