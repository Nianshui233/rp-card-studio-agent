# 阶段边界

阶段顺序：项目定位 → 材料整理（可选）→ 世界观 → 角色 → 系统（可选）→ 场景（可选）→ MVU/EJS（可选）→ 叙事与开场 → 状态栏/UI（可选）→ 整合交付。

每次只询问当前阶段能直接写入的内容。用户主动提供越界信息时记录到跨阶段待办，不继续追问。

## UI 需求访谈

完整执行 `internal-skills/st-frontend-authoring/references/ui-requirements-interview.md`。每轮最多询问 3–4 个当前阶段关键问题；先整理已有世界、角色、系统、变量和开场事实，只询问缺失、冲突或会改变玩家体验的部分。

状态栏/UI阶段的第一轮只确认持续消息界面的四类方向：

1. 主要帮助玩家看什么、做什么，以及最常见的使用旅程；
2. 轻型、轻中型、中型、重型或超重型；用户不懂时按功能需求推荐；
3. 手机、电脑或同等优先，以及是否接近主要游玩表面；
4. 哪些内容必须一眼看到，哪些可以进入标签页、折叠或详情。

后续轮次再分别完成字段与空态、数据规模、交互和反馈、视觉方向、主色、信息密度、主题切换与载体决定。每轮都给 2–3 个项目专属方向和一个明确推荐，用户选定后立即输出可合并的产品方案或源码片段。

旧卡改造的 UI 访谈不得压缩成这一轮四选项。若材料中已经有 UI，必须先完成“现状审查轮”与“目标体验轮”：前者盘点现有页面、正则、脚本、数据来源、玩家路径、优点、故障和保留/重做/删除清单；后者再确认规模、信息层级、交互、视觉、设备和验收。两轮未完成前，不得写 UI 源码、执行 `ui-build` 或进入整合。用户只说“继续/下一步”而没有回答未决问题时，停留在当前访谈轮；只有明确授权“UI 完全交给你”后，Agent 才能自行补齐并锁定，但仍必须先报告现状审查结论。

不要求用户发明正则触发词、XML 标记、变量路径、API、事件或输出模式。用户已经给出标记时沿用；没有给出时由 Agent 生成稳定、中文、唯一的标记，并在后续闭合生产者、prompt/display 正则和数据读取链。

“我不懂，给我推荐”时给方案；“完全交给你/你决定”时直接选择、解释、锁定并执行，不再把已授权内容重新问一遍。

等级衡量视觉、信息架构、交互和 JavaScript 深度，不按页面数、代码行数或动态变量数量配额。另行记录 `data_density`：稀疏变量不等于轻型 UI，允许“重型 UI + 稀疏变量”。前端可用静态项目模块、派生视图、本地交互和完整空态支撑体验，但不得伪造动态事实；如果确实缺少会影响后续裁决的动态事实，向 `mvu_ejs` 交接而不是自动降级。

## MVU/EJS 边界

系统阶段确定“状态代表什么、怎样变化”；MVU/EJS 阶段把已确定语义实现成真实文件。不要在 MVU/EJS 阶段重新设计世界或玩法，也不要把实际代码改写为通用配置。

## 叙事、开场与 UI 边界

叙事与开场阶段同时决定开场发生什么、模型看到什么、初始化是什么，以及首条介绍/创角前端如何呈现和交互。若创角表单会改变运行时数据，还要在该阶段定义 `creation_bridge` 的字段绑定、提交路线和读回。开场前端的视觉与按钮实现也在该阶段完成。

复杂开局通常使用短标记：display 正则替换成完整 HTML，prompt 正则给模型留下短说明。普通叙事开场直接投影到 `first_mes`/`alternate_greetings`。后续状态栏/UI阶段不得重新设计或接管该首楼应用，只处理进入RP后的持续消息界面。

## 返回前置阶段

只有当前阶段确实无法可靠继续时，才返回前置阶段补最小缺口；修完后恢复当前阶段，不重做整个项目。

## NSFW

NSFW 只在预检确认一次。启用后自然并入相关阶段，不再设置问卷或运行门禁；不启用则不主动加载专项模板，但不净化已有材料。若材料涉及未成年人的成人性内容，只在制作期清理/不迁移；不得把清理动作变成最终卡里的年龄确认、18+ 提示、拒绝指令、MVU/EJS 年龄判断或其他运行时门禁。
