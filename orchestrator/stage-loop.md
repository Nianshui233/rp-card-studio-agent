# 固定创作阶段状态机

状态机只用于当前对话中的创作导航，不写入文件，不建立账本、阶段记录、决定锁、访谈表或交接表。

## 固定顺序

```text
preflight
→ positioning
→ materials（有材料、旧卡或转换时）
→ worldbuilding
→ character
→ systems（预检启用时）
→ scenes（预检启用时）
→ mvu_ejs（预检启用或后续确认需要时）
→ narrative_opening
→ status_ui（预检启用或后续确认需要时）
→ qa_delivery
```

未启用的可选阶段到达时直接跳过，不为“跳过”生成记录或报告。

## 阶段内部循环

```text
问当前阶段的一组问题
→ 用户回答、补充或授权 AI 决定
→ 立即写出或修改真实内容/代码
→ 若当前阶段仍有实质缺口，继续下一轮问题
→ 内容足以支持后续时，在对话中给出阶段总结报告
→ 进入下一个启用阶段
```

- 访谈可以多轮，每轮可以有多个相关问题；按内容需要决定数量，不设固定题数。
- 已经回答的事实不重复问。
- 不在提问时制作访谈记录、选择表或决定清单。
- 用户授权 AI 决定后直接写，不逐项等待确认。
- 每次回答后都应产生实际内容或修改；不要连续数轮只收集信息而不落内容。
- 阶段完成时必须在当前对话中给出一次总结报告；总结不写入文件，也不生成独立报告制品。

阶段总结报告包含：

1. 本阶段实际完成的内容；
2. 已确定的关键事实与规则；
3. 仍存在但不阻断后续的薄弱点或可选增强；
4. 下一启用阶段及其目标。

总结应基于已经写出的内容，不复述完整访谈，不制作决定账本。

## 进入与返回

- 新建完整项目从 `positioning` 开始。
- 旧卡修改、审查或转换在定位后先经过 `materials`。
- 继续项目时读取现有文件，判断当前尚未完成的最早相关阶段；不创建恢复状态文件。
- 用户明确只修改某个组件、只审查或只处理 UI 时，可以直接进入该组件所属阶段；完成后只执行相关 QA 与交付，不强迫补做无关阶段。
- 后续实现发现前置内容确实不足时，临时返回拥有该内容的阶段，补完后回到原阶段；不重跑其他已完成内容。

## 阶段完成标准

当前阶段的真实内容已经足以供下游使用，没有会导致后续无法判断或运行的关键空洞。不要因为还能继续扩写、模板还有字段或可以增加更多细节而无限延长访谈。
