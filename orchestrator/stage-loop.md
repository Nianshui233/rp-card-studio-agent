# 固定创作阶段状态机

状态机只用于当前对话中的创作导航，不写入文件，不建立账本、阶段/进度记录、决定锁/日志、访谈表、需求/盘点清单、交接/恢复文件或 QA 过程日志。所有需用户做创作决定的阶段都按 routing 加载 `rp-interview-orchestration`；共用原则见 `orchestrator/interview-playbook.md`，逐阶段触发项见 `internal-skills/rp-interview-orchestration/references/stage-coverage.json`。

## 固定顺序

```text
preflight
→ brainstorm（预检启用时）
→ positioning
→ materials（有材料、旧卡或转换时）
→ worldbuilding
→ character
→ systems（预检启用时）
→ scenes（预检启用时）
→ mvu_ejs（预检启用或后续确认需要时）
→ narrative_opening
→ opening_frontend（需要介绍/路线/创角页面时）
→ message_frontend（需要持续消息 UI 时）
→ qa_delivery
```

未启用的可选阶段到达时直接跳过，不为“跳过”生成记录或报告。

## 脑暴入口与收束

- 预检根据构想完整度给出建议：只有题材、零散画面、人物感觉、相互冲突的方向或整体重构需求时建议启用；已有清晰企划、定向修改、纯审查或纯技术任务时建议跳过。
- 启用后先加载 `rp-concept-brainstorm`，允许用户直接倾倒未经整理的灵感。第一轮必须先展示暂定整合方向，再询问少量承重选择，不以长问卷或专业字段开场。
- 每次用户回答后立即改写母纲、补出可玩动力或写场景证明；用户只对明确授权范围放权时，直接决定并完成该范围；仍未关闭的高影响项继续逐项追问。
- 母纲默认只在当前对话中形成。用户明确要求时可以保存单一当前版 `创作总纲.md`，但不得保存脑暴过程、完成状态、问题答案或修改历史。
- 脑暴足以支撑下游时进入 `positioning`。定位直接继承核心体验、世界动力、关系张力、典型循环与防偏移边界，只补真实缺口，不重复从零发问。

## 阶段内部循环

```text
读取当前阶段覆盖地图并识别已知/未知/不适用项
→ 将未知承重事项拆成独立决策（每轮最多 3 项）
→ 逐项给出问题、建议、理由和影响
→ 用户确认、修正、明确授权代定或明确跳过
→ 立即写出或修改真实内容/代码
→ 对承重内容做具体化、压力/因果或场景证明
→ 让用户校准已经写出的内容
→ 若仍有实质缺口，继续下一轮
→ 内容足以支持后续时给出阶段总结报告
→ 进入下一个启用阶段
```

- 纯路径、开关、文件位置等操作事实可以直接询问；创作取舍必须由 Agent 先承担分析并提出明确推荐。
- 每轮最多 3 个独立决策点；可以共享背景说明，但必须分别编号、分别可回答，禁止用一个综合题压扁多个选择。
- 用户不需要从零构思：每项先给首选建议，再让用户确认、局部修改或对清楚标出的范围明确授权代定。
- 用户部分回答时逐项映射；已回答的项写入内容，未回答的高影响项保留开放，不因“继续”或沉默自动关闭。
- 每次回答后都应产生实际内容或修改；不要连续数轮只收集信息。
- 标准模式默认完成锚定、具体化、至少一次压力/因果检查和一次内容校准；轻量或深挖按项目风险自动调整。
- 深挖优先作用于会反复出现、会改变选择或会造成大面积返工的承重内容，不为了显得详细增加百科、字段或专业术语。

阶段总结报告包含：

1. 本阶段实际完成的内容；
2. 已确定的关键事实与规则；
3. 采用这些方向的主要理由及其对后续的影响；
4. 仍存在但不阻断后续的薄弱点或可选增强；
5. 下一启用阶段及其目标。

总结应基于已经写出的内容，不复述完整访谈，不制作决定账本。

## 后续阶段变更与局部回退

后续阶段提出的新展示、交互或运行需求若改变前面已确认的游戏事实，不得把它当成纯 UI 补丁，也不得要求用户重做整张卡。先经过访谈控制器分类为已有状态直读、已确认规则的确定性派生、临时 UI 状态或新持久状态/玩法；新状态/玩法回到覆盖地图标明的 owning stage 重新确认受影响的语义，再返回当前阶段。只重开依赖链上被影响的决策，保留无关既定内容。若需求仅可逆展示，允许先做标记清楚的草稿；不允许创建影子变量或把未定内容冒充已接通。

## 进入与返回

- 新建完整项目在预检启用脑暴时从 `brainstorm` 开始，否则从 `positioning` 开始。
- 旧卡修改、审查或转换在定位后先经过 `materials`。
- 继续项目时读取现有文件，判断当前尚未完成的最早相关阶段；不创建恢复状态文件。
- 用户明确只修改某个组件、只审查或只处理 UI 时，可以直接进入该组件所属阶段；完成后只执行相关 QA 与交付，不强迫补做无关阶段。
- 后续实现发现前置内容确实不足时，临时返回拥有该内容的阶段，补完后回到原阶段；不重跑其他已完成内容。

## 阶段完成标准

脑暴阶段完成不是因为灵感数量足够，而是零散构想已经成为可供定位直接消费的可游玩母纲：有统一核心、反复体验、自主变化、关系或利益张力、典型循环、开局与升级方向，并至少经过一次具体场景、失败或无人介入检验。

其他阶段的真实内容已经足以供下游使用：覆盖地图中已触发的承重决策均已由明确材料解决、用户确认、用户明确授权代定或明确跳过；临时假设不能关闭承重项。关键抽象已有可观察表现，至少一个高风险点经过场景、边界或失败压力检查。若用户要先看草稿，可交可逆草稿并指出未定事项；不要因为还能扩写或模板还有字段而无限延长访谈。
