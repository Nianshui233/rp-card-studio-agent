# 固定创作阶段状态机

状态机只用于当前对话中的创作导航，不写入文件，不建立账本、阶段/进度记录、决定锁/日志、访谈表、需求/盘点清单、交接/恢复文件或 QA 过程日志。所有阶段共用 `orchestrator/interview-playbook.md` 的建议式深访合同。

## 固定顺序

```text
preflight
→ brainstorm（预检启用时）
→ positioning
→ materials（有材料、旧卡或转换时）
→ worldbuilding
→ character
→ systems（预检启用时）
→ scenes（预检启用时）
→ mvu_ejs（预检启用或后续确认需要时）
→ narrative_opening
→ opening_frontend（需要介绍/路线/创角页面时）
→ message_frontend（需要持续消息 UI 时）
→ qa_delivery
```

未启用的可选阶段到达时直接跳过，不为“跳过”生成记录或报告。

## 脑暴入口与收束

- 预检根据构想完整度给出建议：只有题材、零散画面、人物感觉、相互冲突的方向或整体重构需求时建议启用；已有清晰企划、定向修改、纯审查或纯技术任务时建议跳过。
- 启用后先加载 `rp-concept-brainstorm`，允许用户直接倾倒未经整理的灵感。第一轮必须先展示暂定整合方向，再询问少量承重选择，不以长问卷或专业字段开场。
- 每次用户回答后立即改写母纲、补出可玩动力或写场景证明；用户放权后直接决定并完成。
- 母纲默认只在当前对话中形成。用户明确要求时可以保存单一当前版 `创作总纲.md`，但不得保存脑暴过程、完成状态、问题答案或修改历史。
- 脑暴足以支撑下游时进入 `positioning`。定位直接继承核心体验、世界动力、关系张力、典型循环与防偏移边界，只补真实缺口，不重复从零发问。

## 阶段内部循环

```text
识别当前最有价值的缺口
→ 提出问题，并给出建议、理由和影响
→ 用户确认、修正或授权 AI 决定
→ 立即写出或修改真实内容/代码
→ 对承重内容做具体化、压力/因果或场景证明
→ 让用户校准已经写出的内容
→ 若仍有实质缺口，继续下一轮
→ 内容足以支持后续时给出阶段总结报告
→ 进入下一个启用阶段
```

- 纯路径、开关、文件位置等操作事实可以直接询问；创作取舍必须由 Agent 先承担分析并提出明确推荐。
- 一轮可以有多个相关问题，但不能只给无解释的问题清单。多个问题可以共用建议、理由和影响。
- 用户不需要从零构思：可以直接接受建议、修改局部，或授权 Agent 决定。
- 已经回答的事实不重复问。用户放权后直接写，不逐项等待确认。
- 每次回答后都应产生实际内容或修改；不要连续数轮只收集信息。
- 标准模式默认完成锚定、具体化、至少一次压力/因果检查和一次内容校准；轻量或深挖按项目风险自动调整。
- 深挖优先作用于会反复出现、会改变选择或会造成大面积返工的承重内容，不为了显得详细增加百科、字段或专业术语。

阶段总结报告包含：

1. 本阶段实际完成的内容；
2. 已确定的关键事实与规则；
3. 采用这些方向的主要理由及其对后续的影响；
4. 仍存在但不阻断后续的薄弱点或可选增强；
5. 下一启用阶段及其目标。

总结应基于已经写出的内容，不复述完整访谈，不制作决定账本。

## 进入与返回

- 新建完整项目在预检启用脑暴时从 `brainstorm` 开始，否则从 `positioning` 开始。
- 旧卡修改、审查或转换在定位后先经过 `materials`。
- 继续项目时读取现有文件，判断当前尚未完成的最早相关阶段；不创建恢复状态文件。
- 用户明确只修改某个组件、只审查或只处理 UI 时，可以直接进入该组件所属阶段；完成后只执行相关 QA 与交付，不强迫补做无关阶段。
- 后续实现发现前置内容确实不足时，临时返回拥有该内容的阶段，补完后回到原阶段；不重跑其他已完成内容。

## 阶段完成标准

脑暴阶段完成不是因为灵感数量足够，而是零散构想已经成为可供定位直接消费的可游玩母纲：有统一核心、反复体验、自主变化、关系或利益张力、典型循环、开局与升级方向，并至少经过一次具体场景、失败或无人介入检验。

其他阶段的真实内容已经足以供下游使用：承重选择已有明确理由，关键抽象已有可观察表现，至少一个高风险点经过场景、边界或失败压力检查，用户可以继续修改已写内容而不是仍面对空白。不要因为还能扩写或模板还有字段而无限延长访谈。
