# 可选创作、自动技术收尾与宿主发现

## 适用范围

创作取舍仍由真实用户依据决定；已授权制作范围内的检查、修正明确技术错误、构建和整理交付由 Agent 默认执行，不逐项报备。用户明确“先讨论”“只看不改”“不要打包/不要扫描”等限制优先。仅修改 Agent 仓库不意味着要制作或改动作品。自动收尾不自动提交 Git、推送、启动/安装宿主或操作未授权用户数据。

## 可选的叙事与开场

narrative_opening 是可选阶段，新项目初始 unresolved。预检分别确定“叙事规则：新设/沿用/不额外设置”和“开场：新写/保留原文/不制作”；两项决定引用 authority，不另外建状态权威。只需其中一项时只启用其范围，不强制另一项。新写任何一项则启用本阶段，并只访谈对应触发项。已有素材完整且只需保留时，不重访谈或重写。两项都无需新增时，以用户明确选择或本次任务确实不涉及的依据跳过；未回答不得伪装为拒绝。

用户明确跳过用 ledger-event skip 与真实 skip 依据；已制作成果不得靠 skip 抹掉。旧卡定向修改不强迫补做无关可选阶段。旧账本已经启用/制作的叙事阶段不因路由变成可选而自动关闭。

开场创作、开场前端、消息前端独立选择。介绍/创角页面可以仅消费已有世界资料，不强制新写开场；若页面含开场选择则必须有真实 Greeting 映射。不新写开场不免除已有文本的一致性、玩家边界、协议和初始化检查。first_mes/alternate_greetings 如需保持空白，按目标宿主导入合同检查，不为通过检查擅自塞入占位剧情。MVU 使用 greeting 初始化而没有有效 Greeting 时，返回 MVU 合同明确处理初始化路径，不伪造剧情、静默切换策略或跳过初始化。

## QA 与交付默认执行

阶段内部自动检查当前成果，不等用户催。当前授权范围形成实际成果、承重未决项已解决后，默认自动终检、按当前选定路线构建/整理导入包与制作文件，最后一次性报告路径、结果与限制，不先问“是否进行 QA/是否打包”。未到收尾条件时只做阶段内检查，不提前要求后续组件实现。

全项目收尾用 selected_project：已启用实质阶段必须已经提交/接受，启用待定先解决；定向修改用 current_stage：只承接当前已授权交接，不强迫做无关阶段，也不能宣布整个项目已完成。未解决范围可以交可逆草稿并标明，但不得进入自动成功交付。

确定性转换器的 auto-qa 事件写入 qa_delivery.automaticExecution，引用已授权制作阶段的 entryEvidence 和 handoffId，不创建新的 userEvidence、authorizations 或创作决定。来源待交接转为 authored（制作已提交、用户待审阅），腾出技术收尾活动阶段，不改成 closed/accepted。源交接/许可变化、承重未决或用户否决使自动依据失效。新创作阶段仍需自己的真实许可。已有成果要修改时使用 ledger-event reopen 与该阶段真实 start/delegate 依据，撤销受影响的旧 QA 当前结果、重开制作与审阅，不保留旧 accepted 完成态；此后新交接可再次自动收尾。authored 的旧成果可由用户对其原交接明确接受，不能由 QA 接受代替。

执行命令：

```text
node scripts/production/automatic-qa.mjs --root <项目目录> --scope current_stage|selected_project
```

执行前按路由读 QA 主/支援模块与本合同。用户明确禁止扫描或宿主缺少该能力时可传 --skip-discovery --discovery-reason <真实原因>，当前记录标未检查，不沿用旧发现。已有明确环境偏好随当前记录复核，可用 --host-origin/--host-directory 指定本次目标；不借扫描取得实机变更许可。命令主动发现宿主、继承制作范围、锁定 QA 路由、使 production.activeStage 跟随账本、执行已有统一构建检查计划、复核精确导入文件/世界书/运行组件和两目录交付、最后提交 delivered/pending 的技术交接。技术交付不占用创作活动阶段、不要求用户再批准 QA 才能处理新的明确创作请求；新创作仍需自身真实许可，单独“继续”不授予该许可。同一交接不重复自动收尾，新交接才重新执行。应先由 owning skills 准备实际源码、检查计划、选定导入文件和唯一导入说明，不能用空计划或单一假检查冒充完整 QA。没有运行组件的内容项目也需完整的相关检查计划和调度合同。

任何检查失败停止，QA 标 blocked，修复后重跑，不能把失败或未运行刷成成功；不进行无限自动修复。调整技术实现不得删功能、降低用户选定规格、篡改 RP 内容或擅自关闭组件；新创作取舍返回拥有该内容的阶段。命令不执行实机导入/消息生成、不设置 runtime/human/release 为 passed；静态、离线/browser-fixture、真实宿主和用户验收分别报告。已整理文件可交付待验收版本，不能说“用户已接受”“可直接导入”“最终完成”。

## 默认只读宿主发现

新项目启动执行；续接时复核已有当前记录，环境改变/进入实机 QA 前重新执行。记录覆盖写入制作文件/项目记录/host-environment.json，只保存当前安装路径、配置候选、可访问地址、探测范围和限制，不保留扫描历史或进入导入包。

```text
node scripts/host/discover-sillytavern.mjs --project-root <项目目录>
```

可用 --directory、--scan-root、--origin、--preferred-directory、--preferred-origin 指定本机候选；重复参数可给多个目录/地址。不硬编码当前机器路径、默认端口或账户。先处理明确路径/进程/监听端口，再做有深度、目录数量和耗时限制的磁盘目录发现。验证安装特征而非只认目录名；避免数据/聊天目录和链接，不读取聊天、API 密钥或原始配置全文，不持久化原始进程命令行。配置候选和进程可解释的启动参数仍不证明实际环境覆盖值。

四层结论必须分开：有安装文件；监听进程候选；页面签名证实服务可访问；当前账户/扩展/测试条件。脚本只达到前面可证实的层级，账户和扩展默认 not_verified，runtime 始终 not_run。认证、跳转、超时、无端口读取权限和扫描上限均留下限制，未发现只能说“本次可见范围未发现”。当前执行环境可能是远程机器/容器，不冒充扫描了用户物理电脑。HTTP 探测仅 GET 本机回环首页，不跟跳转、发送 cookie/凭据、执行页面脚本、端口全扫或使用网络代理冒充本机响应。

唯一明确实例可以默认用于只读核查；多实例优先匹配用户已指定目标，不能明确匹配时只问一次选择，不能靠版本新旧或端口大小替用户决定。发现有安装但未运行不自动启动；发现正在运行不自动导入/覆盖脚本、切换账户或发送测试消息。实机变更只执行已有明确测试授权范围；缺浏览器/文件/进程权限时报告能力不可用，不伪装探测成功。
