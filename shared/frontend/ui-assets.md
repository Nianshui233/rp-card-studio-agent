# UI 字体、图标与 SVG 图形能力

这是字体、图标、SVG 和资源的可选技术资料，不是两种前端共用的设计规则。开场按 opening-design.md、持续消息按 message-design.md 分别选择自己的构图、字体层级、密度与交互；本文件只解释资产实现、来源和载体事实，不规定统一审美或必用资源。

## SVG 是可选的一等图形表达能力

SVG 不只是“换一种图标格式”，也可以承载作品专属的空间、路线、徽章、仪表和关系表达。是否使用由玩家体验和作品语义决定，不要求每个前端都有 SVG。

先区分四类用途：

1. **功能图标**：返回、展开、搜索、物品等通用动作；
2. **作品专属资产**：阵营徽章、印章、旗帜、仪式符号和主题图形；
3. **数据图形**：地图、路线、关系图、资源流向、刻度、进度和状态指示，可由静态世界设定或真实运行数据驱动；
4. **纯装饰图形**：边框、纹理、分隔、背景和氛围，不承载未确认的事实。

用户只需要描述“希望玩家看见什么、怎样理解或操作”；Agent 负责选择 HTML/CSS、内联 SVG 或其他实现。SVG 是表达方式，不是 MVU、mvu.zod、EJS 或酒馆助手的启用开关：静态徽章不要求这些运行能力，动态或交互图形只接入已经确认的真实数据与宿主。用户指定图形、提供充分参考或授权自由设计时，不重复提问。不要让用户学习 `viewBox`、路径和代码。

### 实现合同（采用 SVG 时）

- **自包含与载体**：默认内联 SVG，图形自身无需额外联网；这不代表其字体、宿主插件或其他资源也已离线。远程资源仍按用户选择登记与回退。TH/STPT iframe 内的 SVG 可由该页面 JavaScript 绑定数据/交互；`<img>` 或 CSS 背景中的 SVG 是图片，不能把其中脚本或内部节点点击当作页面交互。纯 ST 的净化展示需要目标宿主证据，不因浏览器预览正常就宣称可用。
- **响应式**：独立图形有有效 `viewBox`（四个有限数值，宽高为正），再设置容器尺寸和 `preserveAspectRatio`；检查是否裁掉文字、压扁徽章、溢出消息或形成双重滚动。不能只把整张图缩小到手机看不清；密集地图/关系图可以缩放、分层、点开详情或切换文字视图。
- **可访问语义**：纯装饰 SVG 用 `aria-hidden="true"` 并不占键盘焦点；信息型静态图可用 `role="img"` 配合 `<title>` / `aria-labelledby` 或等价名称，复杂地图/图表还提供可读的结构/数值说明。交互容器不能一律套成整体 `role="img"` 隐藏内部控件；用原生按钮/链接、等价文字操作，或实现有名称、焦点与键盘激活的图形控件。不能只靠颜色、形状或悬停表达重要状态。
- **引用隔离**：同一文档内的 `<title>`、`<desc>`、渐变、滤镜、`clipPath`、`mask`、`marker` 和 `<symbol>` ID 按图形/实例唯一，`url(#...)`、`href="#..."` 与 ARIA 引用一起更新。iframe 之间是独立文档；纯 ST 同文档多消息不能复用全局 ID。禁止为了 SVG 再增加消息清理正则或组包含。
- **真实数据**：静态设定、实时状态和确定性派生视图分开。标签、位置、连线、刻度和可操作路线消费唯一来源，不创建影子状态；没有主控时仍可画世界，主控切换和 Swipe/编辑后同步当前快照，不能残留上一个主控的私人关系。新增玩法/持久字段回 owning stage 和 MVU 合同，不在画图时临时捏造。
- **动态输入边界**：Agent 编写并检查的 SVG、JavaScript、动画和交互属于正常维护源码，不因“模型写了代码”而禁止。游玩时的不可信模型文本、用户输入和远程内容作为数据处理：文字用 `textContent`，数值用有限值/范围校验，状态映射到受控样式；程序创建 SVG 节点时使用 `createElementNS`。若明确需要运行时图形载荷，先解析并限制其元素、属性、URL 和执行能力，再接入已验证宿主，不把未经处理的文本拼成 SVG/HTML/脚本。
- **动效与复杂度**：渐变、滤镜、路径动效和 SVG/HTML 混排可按作品需要使用，不设置行数/节点数创作上限；按实际手机性能、`prefers-reduced-motion` 和页面卸载清理调整，不因“复杂”抹掉用户选定的体验。
- **异常回退**：图形故障时给文字、列表、数值或 CSS 版本；数据缺失时显示未知/空态，不把旧值或 mock 当当前数据。回退是异常路径，不是静默降级；用户选定的图形和交互必须仍有正式实现与验收，宿主确实不支持时先报告阻碍与替代路线，不擅自改成文字。

### 验收抓手

只检查实际采用的功能，不对纯文字项目要求 SVG：

- 使用项目真实内容核对图例、地点/连接、数值和当前主控边界；
- 窄屏、长中文、未知/零值、图形故障、键盘/触控、重复实例和 ID 引用；
- 动态图形增加当前楼层/Swipe、编辑、主控切换和持久化后刷新检查；
- 图形和文字操作表达同一动作，不能一个只是选择、另一个偷偷发送或改状态；
- 用户选择图形时检查其已实现，未使用 SVG 本身不构成错误。没有真实宿主测试时写 `runtime: not_run`。

“用了 SVG”不是完成标准；信息架构、真实数据链、交互和作品个性仍需独立验收。不要只把 emoji 换成统一描边图标：专属符号应承接作品的时代、材质、制度与媒介，并融入构图，而不是贴在通用卡片上。

## 1. 字体与功能图标的分工

### 字体

字体负责：

- 中文长文本的可读性；
- 时代、地域、职业和世界观气质；
- 标题、正文、数据标签的层级；
- 像素、档案、手写、古典、工业、终端等视觉签名。

字体不是装饰性最后润色。先确认正文可读性、字重、行高、窄屏换行和系统回退，再决定是否使用特殊展示字体。

### 图标

图标负责：

- 搜索、返回、关闭、展开、设置、刷新等通用动作；
- 人物、物品、任务、地图、事件、警告等信息识别；
- 触控按钮的快速识别。

功能图标和世界观美术要分开：图标库适合承载动作和通用语义，阵营徽章、仪式符号、特殊纹章和主题装饰应使用项目自己的 SVG/CSS/图形资产。

## 2. 可选资源来源

### ZeoSeven Fonts

适合中文字体检索、风格对比、字重选择和 Web 字体调用。Agent 可以根据 RP 主题先给出字体方向，再由用户选择或授权 AI 决定。具体字体的许可、语言覆盖、字重和嵌入方式以该字体页面为准，不把整个站点笼统标成一个许可证。

可选实现路线：

1. `design_reference`：只用于选型和风格说明，不进入运行时；
2. `remote_font`：通过远程 CSS/字体服务加载，必须登记远程依赖、版本/来源、系统字体回退和 `runtime` 证据；
3. `local_font`：下载需要的字重并放入项目维护源码；
4. `embedded_subset`：只嵌入项目实际需要的字形或局部字体，适合追求离线一致性的项目。

不要默认把完整 CJK 字体塞进角色卡。字体很大时，远程字体 + 可靠系统回退、局部子集或普通系统字体都可以是合理选择；由用户体验目标、网络环境和制品大小共同决定，不能用体积作为创作上限。

### Font Awesome Free

适合功能性图标和常见操作语义。默认优先提取实际使用的 SVG 并内嵌到最终 HTML；只有确实需要字体图标或完整图标运行时，才选择自托管 Web Font 或 SVG/JS 路线。

推荐顺序：

```text
项目专属 SVG/CSS 装饰
→ Font Awesome Free 的选定 SVG 功能图标
→ 字体图标（仅在有明确理由时）
→ 远程 CDN/Kit（仅在用户接受远程依赖时）
```

不要把完整 `all.css`、`all.js` 或整个图标字体库无差别装进角色卡。只保留使用到的图标、样式和必要代码，避免增加加载失败面与无意义体积。品牌图标只在实际使用时于最终交付说明中注明，不把品牌标志当普通装饰。

## 3. 资产策略落地

用户只需表达“希望更像旧报纸”“按钮要清楚”“不要外链”“可以接受联网加载”等体验偏好；Agent 直接把选择落实到实际 HTML/CSS/SVG 和回退代码中，不生成资产需求表、来源清单、许可账本或中间 YAML。

只有最终页面真实使用的远程字体、图标库或外部资源，才在最终导入说明中简短列出具体资源、版本/来源、许可、联网要求和失败回退。内嵌 SVG、系统字体和未进入成品的设计参考不另建记录文件。

## 4. 玩家端规则

- 正文默认优先可读性，特殊字体只用于标题、标签、徽章或主题区域；
- 中文字体必须检查长文本、标点、数字、英文、缺字和窄屏换行；
- 图标按钮必须有中文可见文字或可访问名称，不能只靠图形猜意思；
- 图标不能只用颜色表达状态；危险、选中、禁用和成功状态要有文字、形状或辅助说明；
- 触控目标和间距按照实际移动端体验检查；
- 明暗主题若启用，字体、图标、边框和状态对比度必须分别检查；
- 远程资源失败时必须保留可读文字、系统字体、内联 SVG 或 CSS 回退；
- 不能把“使用了字体/图标库或 SVG”误当成 UI 完成，信息架构、交互和真实数据链仍需独立完成；
- SVG 有动态数据时，检查空值、未知、窄屏、键盘/触控、文字回退和属性边界。

## 5. 独立设计与资产实现

两种前端不自动共享视觉方向、字体、密度或组件规则。用户明确希望呼应时，分别说明为什么适合各自任务，而不是复制一套皮肤。可复用确定性的技术实现和实际资产，但不共享运行时状态权威或生命周期；最终页面不能通过未交付的本地路径依赖另一个页面。开发工程由实际复杂度决定，不强制也不禁止。

制作时查看外部设计、实际使用资源、执行游玩文本是三个不同边界。公开设计、图片、字体和组件文档可以主动研究；采用资源后核对许可、版本和真实表现，不因“自包含”推导出必须零外链。完整视觉预览按 layout-preview.md 使用核对后的实际资源字节，断网失败场景单独测试，不能拿缺资源的画面代替完整设计。

## 6. 与 SillyTavern 交付的关系

字体、图标和 SVG 图形可以出现在：

- 开场介绍/创角 HTML；
- 持续消息状态 HTML；
- 超重型/0 层消息应用；
- 用户明确要求的其他卡内 HTML 表面。

它们不能默认要求修改 SillyTavern 本体或全局安装插件。远程字体或图标库属于项目运行依赖；最终报告必须说明：

- 是否需要联网；
- 失败时显示什么；
- 是否有系统字体或内联 SVG 回退；
- 是否在真实 SillyTavern 中验证过；
- 使用的具体资源、版本/来源和许可。

## 7. 不增加创作上限

资产策略只负责可运行性、可读性、可回退性和必要的最终来源说明，不限制：

- 字体数量；
- 图标数量；
- SVG 行数；
- UI 页面数量；
- 远程资源数量；
- 最终 HTML 或角色卡大小。

性能和加载成本只作为报告与优化建议。只有资源断链、无法读取、导致页面空白或让核心操作失效时，才进入整合阻断。
