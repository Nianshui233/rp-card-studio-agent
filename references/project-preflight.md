# 项目预检

项目预检是每次调用的第一阶段，只负责确认“在哪里工作、处理什么、读取什么、交付什么”。这一阶段不讨论任何创作内容，也不创建项目文件。

## 预检目标

在进入项目定位或已有项目处理前，获得一份明确、可执行的项目环境约定：

- 用户明确指定的工作区。
- NSFW 开关的明确状态。
- 本次任务类型。
- 已有材料的位置或“无材料”的明确结论。
- 项目阶段路线。
- 交付目标。

用户已经在调用语句中明确提供的内容直接采纳，不重复询问。

## 允许问题

只允许询问以下事项：

1. **工作区**
   - 本次项目使用哪个明确目录。
   - 这是已有项目目录，还是用户准备给新项目使用的位置。
   - 用户说“当前目录”时，将其解析成绝对路径后复述确认；不要保留含糊相对路径。
2. **NSFW 开关**
   - 只问“启用”或“不启用”。
   - 用户已明确表达成人向或明确关闭时，直接记录，不重复询问。
3. **任务类型**
   - 新建、继续、转换、修改、审查，或以上组合。
   - 仅在无法从请求判断时询问。
4. **已有材料**
   - 角色卡 JSON/PNG、世界书、小说、设定文档、旧工程等材料的路径。
   - 无材料时要求明确回答“无”。
5. **项目阶段路线**
   - 保持固定顺序：项目定位 → 材料整理（可选）→ 世界观 → 角色 → 系统（可选）→ 场景（可选）→ MVU/EJS（可选）→ 叙事与开场 → 状态栏/UI（可选）→ 整合交付。
   - 首轮必须逐项选择材料整理、系统、场景、MVU/EJS、状态栏/UI：进入或跳过。未选择的阶段写入 `workflow.selected_stages`，后续不得按默认路线进入。
   - 推荐：按项目实际需要选择；材料整理没有材料时跳过，MVU/EJS 和状态栏/UI 不为显得复杂而强行加入。
6. **交付目标**
   - 新建角色卡项目默认锁定且最终只交付一个角色卡 `.json`。
   - PNG、独立世界书、源码归档、UI 工程或额外报告只作附加方向简短提示；只有用户明确说需要才加入。
   - 维护工作区和验证文件是生成 JSON 所需的内部事实源与证据，不自动算作额外最终交付物。

## 禁止问题

项目预检不得询问：

- 题材、基调、核心体验或任何剧情内身份。
- 世界规则、时代、势力、历史或秘密。
- 角色姓名、性格、动机、关系或说话方式。
- 数值轴、阈值、公式或更新逻辑。
- 场景结构、线索、事件或地图。
- MVU 变量设计、EJS 模板实现或脚本细节。
- 叙事视角、开场白内容或文风。
- 状态栏字段、布局、配色或交互。
- NSFW 的偏好、边界、清单、强度、角色设定或任何二次确认。

即使某个创作问题看起来“很基础”，也必须等到对应阶段再问。

## 首轮策略

首轮一次列出所有缺失的预检项。每项都给出方向和推荐，但推荐不能替代必须由用户明确指定的工作区与 NSFW 开关。

推荐逻辑：

- 工作区：要求用户给出明确路径；可以示范路径格式，但不能擅自选桌面、当前仓库或任意默认目录。
- NSFW：若用户希望个人 RP 保持最大创作自由，推荐“启用”；若只是不想主动加载专项成人模板，选择“不启用”。两种选择都不会向游玩模型安装拒绝规则或运行时门禁。
- 任务类型：根据用户动词和输入材料推断；有把握时直接报告推断结果。
- 材料：有旧项目时推荐只读导入并保留原件；无材料时不要求为了流程而准备材料。
- 阶段路线：若用户没有逐项指定，给出“按默认完整路线 / 跳过材料整理 / 跳过系统 / 跳过场景 / 跳过 MVU/EJS / 跳过状态栏/UI / 自定义组合”等方向，并推荐一项；等待用户选定后把完整有序数组写入 `workflow.selected_stages`，同时锁定 `preflight.workflow_confirmed: true`。已有项目已锁定的路线保持不变。
- 交付：新建角色卡项目直接采用“一个角色卡 `.json`”作为默认值。简短说明“如明确需要，也可附加 PNG 等制品”；用户没有明确选择时不加入、不生成。已有项目已锁定的交付物保持不变。

首轮格式：

```markdown
开始前先确定本次项目环境。我只询问尚未明确的项目预检信息：

1. **工作区**：[问题]
   - 可选方向：[已有项目目录 / 为新项目指定一个目录]
   - 推荐：[结合请求给出的建议]
2. **是否启用 NSFW**：请选择“启用”或“不启用”。
   - 推荐：[建议及一句理由]
3. **已有材料**：[问题]
   - 推荐：[只读导入 / 明确为无]
4. **项目阶段路线**：材料整理、系统、场景、MVU/EJS、状态栏/UI 分别进入还是跳过？
   - 推荐：[结合项目目标给出完整有序路线；用户选择后记录到 `workflow.selected_stages`]
5. **附加交付物**：默认最终只交付一个角色卡 `.json`；是否还明确需要 PNG、独立世界书等附加制品？
   - 推荐：无附加项；需要时请明确列出。
```

只列缺失项，编号不必固定。如果只缺一项，就只问这一项。阶段路线不能默认为“没回答就全部进入”：没有 `workflow_confirmed` 和 `workflow.selected_stages` 时，不得进入项目定位。

## 工作区规则

- 工作区必须来自用户的明确指定，不从当前终端目录、文件所在目录或历史项目推断。
- 用户指定已有路径后，可以只读检查是否存在、是否可访问以及目录中有哪些候选材料。
- 用户指定尚不存在的路径时，记录为新项目目标，但本阶段不创建它。
- 路径不存在、指向单个文件却被称为工作区、或包含多个难以区分的项目时，只追问路径归属，不转入创作问题。
- 原始输入永远不是默认输出位置。修改或转换任务也应把生成结果写入已指定工作区。

## NSFW 开关规则

状态只允许：

```yaml
nsfw: enabled
```

或：

```yaml
nsfw: disabled
```

这个开关只是作者侧的创作元数据，不是面向游玩模型的安全门禁，也不是角色卡运行时变量。

- `enabled`：视为用户对成人与成熟内容维度完全放权。后续不再询问强度、偏好、许可、边界或限制；按人物、关系、世界、系统和 UI 的正常需求自然创作，并在确认存在角色时加载角色 NSFW mix-in，在状态栏/UI 中加载对应模板。
- `disabled`：不主动加载或扩写专项成人模板，但不反向审查、删除、净化或阻断用户材料中已有的成熟内容，也不阻止 RP 自然出现灰色或成人主题。
- 两种状态都不得向 CharacterBook、开场、系统提示、MVU/EJS、UI 或其他模型可见产物投影“NSFW 已启用/已关闭”、拒绝规则、内容分级卡、运行时 gate 或 UI 开关，除非用户明确把它设计成玩法机制。

没有明确答案时预检尚未完成；一旦锁定，后续阶段不再把它当成问题主题。

## 信息采集与只读检查

用户回答后：

1. 将工作区解析为绝对路径。
2. 对已有路径做只读检查，不修改原始材料。
3. 列出识别到的材料类型、无法识别项和路径问题。
4. 根据材料与交付目标报告推断出的任务类型；若推断存在实质分歧，再给方向让用户选。
5. 生成预检片段，等待用户确认进入项目定位或相应处理阶段。

已有工程在预检锁定后、执行任何阶段更新或校验前，必须把本轮任务类型事务式写回 `project.project.operation`：继续使用 `state <workspace> operation continue`，修改使用 `edit`，审查使用 `audit`，只处理 UI 使用 `ui`。这个字段表示当前工作轮次，不是项目最初怎样诞生。`create` 只由 `init` 写入，`convert` 只由 `unpack` 写入；不要手改，也不要让续作工程继续残留 `create`，否则可选阶段会把“保留既有实现”误判成“新建时跳过却偷带实现”。

## 充分性门槛

以下条件全部满足才可结束预检：

- 工作区是用户明确指定且已解析的绝对路径。
- NSFW 已明确为 `enabled` 或 `disabled`。
- 任务类型已明确，或已从请求可靠推断并向用户报告。
- 已有材料已列出并可访问，或用户明确表示无材料。
- 交付目标至少有一项且与任务类型不矛盾；新建角色卡未指定附加项时自动锁定且仅锁定 `character_card_json`。
- 路径冲突、读写位置混淆等工程阻塞已解决。

## 轮次输出格式

````markdown
## 本轮已锁定
- 工作区：[绝对路径]
- NSFW：[启用 / 不启用]
- [本轮其他明确项]

## 本轮预检片段
```yaml
workspace: "D:/RP/projects/midnight-train"
operation: create
nsfw: disabled
materials: []
deliverables:
  - character_card_json
```

## 预检检查
- 已满足：[列出]
- 仍缺少：[只列预检项]

## 下一步
[继续询问缺失预检项，或给出阶段总汇]
````

该片段仅用于对话确认；新建项目在项目定位总汇确认前不落盘。

## 示例片段

用户说：

> 用这个技能帮我从零做卡。

正确首轮：

```markdown
开始前先确定本次项目环境：

1. **工作区**：请指定本项目使用的目录。如果目录还不存在，也请先定下准备使用的完整路径。
   - 推荐：为本项目使用单独目录，便于保存源码、构建产物和报告。
2. **是否启用 NSFW**：请选择“启用”或“不启用”。
   - 推荐：个人自用且希望保留最大创作自由时选择“启用”；只是不想主动加载专项成人模板时选择“不启用”。
3. **已有材料**：是否有旧卡、世界书、小说或设定文件？有则提供路径，没有请回答“无”。
   - 推荐：旧材料只读导入，成果输出到工作区。
4. **附加交付物**：默认最终只交付一个角色卡 `.json`。是否还明确需要 PNG、独立世界书或其他附加制品？
   - 推荐：无附加项；确实需要时再明确添加。工具支持 PNG 不等于默认生成 PNG。
```

错误首轮包括：“世界是什么时代？”、“角色性格偏冷淡还是热情？”、“需要好感度吗？”这些都属于后续阶段。

## 阶段总汇

预检充分后，输出完整环境总汇、只读检查结果，以及尚未创建任何文件的说明。

## 下一阶段建议

- 新建项目：推荐进入“项目定位”。
- 有材料的转换或修改：仍先进入“项目定位”确认本次目标，再进入“材料整理”。
- 纯审查：推荐进入“项目定位”界定审查目标，随后按问题所在阶段路由。

正常模式下等待用户确认进入项目定位。若整个项目已被用户明确完全放权，报告路由选择及理由后直接进入，但仍不得在项目定位总汇由用户确认或由 AI 按授权报告并锁定之前创建新项目目录。
