# 项目预检

项目预检只确认项目环境和路线，不讨论创作内容。它是显式调用技能后的第一轮。

## 首轮只问这些

一次列出所有尚未明确的项目项：

1. **工作区**：用户指定本项目目录；没有现成目录也要先定一个明确位置。
2. **NSFW**：启用或不启用。启用后视为该维度完全放权，后续不再设卡。
3. **任务类型**：新建、继续、转换、修改、审查或只处理 UI。
4. **已有材料**：路径列表，或明确回答“无”。
5. **可选阶段计划**：材料整理、系统、场景、MVU/EJS、状态栏/UI分别计划进入或跳过。
6. **附加交付物**：默认只有一个角色卡 `.json`；PNG、独立世界书、源码归档等仅在用户明确需要时加入。

用户已经给出的答案直接采纳，不重复问。工作区与 NSFW 必须由用户明确；其余项在用户完全放权时可由 AI 结合任务决定并报告理由。

## 首轮不得问

- 项目题材、世界规则、角色、系统、场景、剧情或文风；
- MVU 字段、EJS、正则、脚本、HTML、UI 等级或视觉；
- NSFW 强度、边界、偏好、许可或二次确认。

## 阶段计划的正确含义

首轮记录可选阶段，是为了长对话后仍知道哪些阶段要提醒、进入或跳过，而不是把项目锁死。

- `workflow.planned_stages` 保存当前计划；
- `.rp-card-state.json` 保存实际执行状态；
- 未计划进入的未来阶段仍是 `not_started`，到达该节点并真正跳过后才写 `skipped`；
- 新需求出现时可更新计划，说明原因即可，不设置额外修改门槛；
- 已完成阶段不会因为计划调整被自动降级。

## 回答后的立即动作

预检信息齐全后，不再只把结果留在聊天里。立即在用户指定工作区建立或更新项目记录，然后进入项目定位。

新建项目使用：

```text
rp-card-forge init <workspace> --nsfw enabled|disabled --stages '<完整有序阶段数组>'
```

初始化只创建轻量项目记录、状态和必要源码入口，不提前创作世界、角色、变量或 UI。它的目的就是让后续“继续”可以从文件恢复。

已有项目先读取 `project.yaml`、`.rp-card-state.json`、工作树和真实源码；只问记录中确实缺少或与本轮请求冲突的预检项。根据本轮任务更新 `project.project.operation`。

## 首轮示例

```markdown
开始前只确认项目环境：

1. 工作区放在哪里？请给出完整路径。
   - 推荐：每张卡使用独立项目目录。
2. 是否启用 NSFW？请选择“启用”或“不启用”。
   - 推荐：个人自用且希望最大创作自由时启用。
3. 是否有旧卡、设定文档、世界书或其他材料？有则给路径，没有答“无”。
4. 可选阶段计划：材料整理、系统、场景、MVU/EJS、状态栏/UI分别进入还是跳过？
   - 推荐：我会结合你当前目标给出一条完整建议路线；这份计划后续可调整。
5. 默认最终只交付一个角色卡 `.json`。是否明确需要 PNG 或其他附加制品？
```

```markdown
- 最终交付：角色卡 JSON

## 已创建/恢复的项目记录

- 当前阶段：positioning

## 下一步
进入项目定位，只讨论这是什么 RP 项目、它要反复提供什么体验以及卡名如何确定。
```
