# 项目定位阶段

本阶段把模糊想法收敛成一份可指导后续设计的 RP 项目方向。从宿主和使用视角看，导入的 SillyTavern 角色卡 JSON/PNG 本身就是完整 RP 项目的可移植部署包，不是空壳或某个人物档案；世界、人物、系统、场景、脚本和 UI 是平级模块。从维护视角看，`project.yaml + src/` 才是源项目，JSON/PNG 是完整部署投影。本阶段回答“这个项目要让谁体验什么”，不回答世界如何运行、角色具体是谁或系统怎样计算。

## 本阶段产物

形成一份简洁的 `positioning` 片段，至少说明：

- 一句话项目命题。
- 面向完整 RP 包的中文项目标题，以及非空、不包含任何角色档案的项目级入口 `card_entry`。
- 目标用户与用户在 RP 中的参与位置。
- 核心体验和体验支柱。
- 题材组合与总体基调。
- 互动结构与用户能动性。
- 项目规模和预期游玩跨度。
- 本项目后续阶段路线建议。

## 允许问题

可以询问：

- 用户最想获得的核心体验，例如调查、陪伴、博弈、成长、生存或经营。
- 题材的大类与组合方式。
- 总体情绪基调、严肃度、压迫感或轻松度。
- 用户在互动中的高层身份与能动性，例如参与者、指挥者、观察者、共同创作者。
- RP 包的承载形态，例如真正单角色、世界/场景、玩法、群像、多角色、叙事者、功能型主持或带锚点角色的世界项目。
- 项目标题如何概括整包的世界、玩法、主题或体验；只有真正单人卡最终使用唯一角色名，其余类型都使用这里锁定的项目标题，不默认用某个角色或单一地区名代替。
- 主导矛盾的类型，例如身份暴露、资源不足、价值冲突、关系拉扯；只定类型，不写具体规则。
- 项目规模，例如短场景、可重复日常、中篇主线、长期沙盒。
- 多种体验发生冲突时的优先级。

`card_mode` 只能从下表选择。这个稳定字段只是决定宿主投影、制品命名和叙事锚点约束的打包分类，不是以角色卡为中心的源项目类型系统。`pending` 只供草稿占位，定位锁定时必须换成正式模式；不要自行发明近似 ID，因为卡名和角色组合校验依赖这项显式分类。

| `card_mode` | 适用承载形态 | 卡名来源 | 固定叙事锚点 |
| --- | --- | --- | --- |
| `single_character_card` | 恰好一个角色，世界与规则只服务于该角色 | 唯一角色名 | 恰好一个 |
| `world_package` | 世界本身是主要体验，可没有固定人物 | 项目标题 | 可无 |
| `scenario_package` | 一个或一组可游玩场景 | 项目标题 | 可无 |
| `gameplay_package` | 规则、循环或功能玩法主导 | 项目标题 | 可无 |
| `ensemble_package` | 群像关系与共同事件主导 | 项目标题 | 可无 |
| `multi_character_package` | 多个可独立调度的人物共同构成项目 | 项目标题 | 可无 |
| `narrator_package` | 叙事者或世界声音主导 | 项目标题 | 可无 |
| `facilitator_package` | 主持、裁判或生成器功能主导 | 项目标题 | 可无 |
| `world_scenario_with_anchor_character` | 世界/场景为主体，但有一个稳定叙事锚点 | 项目标题 | 恰好一个 |
| `gameplay_with_anchor_character` | 玩法为主体，但有一个稳定叙事锚点 | 项目标题 | 恰好一个 |
| `hybrid_package` | 多种项目主体同等重要且无法归入上列 | 项目标题 | 可无 |

## 禁止问题

不得询问：

- 世界的具体年代、力量来源、势力制度、历史事件或规则例外。
- 具体角色的姓名、经历、动机、性格、外貌或语言样例。
- 好感、怀疑、资源等变量的数值范围、公式或阈值。
- 具体地点的出入口、线索、机关或事件表。
- MVU 字段路径、更新命令、EJS 模板或脚本。
- 叙事人称、时态、回复格式或开场白正文。
- 状态栏字段、视觉风格、配色或布局。
- NSFW 的偏好、限制、强度或具体设定。其开关已在预检确定，本阶段不再提及。

若用户主动给出这些信息，按 `references/stage-boundaries.md` 记入目标阶段待办，不展开追问。

## 建议轮次

### 第一轮：体验核心

围绕 3 到 5 项提问：

1. 最希望用户反复做什么选择。
2. 希望这些选择带来什么情绪。
3. 用户在关系或事件中的参与位置。
4. 题材与基调。
5. 核心矛盾类型。

每项提供有实际差异的方向、对 RP 的影响和明确推荐。

### 第二轮：产品边界

在第一轮片段锁定后，再询问：

1. 真正单角色、世界/场景、玩法、群像、多角色、叙事者、锚点角色项目或混合承载。
2. 短篇、循环式、中篇或长期沙盒。
3. 用户能动性的强弱。
4. 两到四个体验支柱的优先级。

信息已由用户明确提供时直接生成片段，不机械凑满两轮。仍有定位层面的真实缺口时才继续第三轮。

## 充分性门槛

以下条件全部满足，本阶段才算充分：

- 能用一句话准确描述“谁在什么类型的困境中获得什么体验”。
- 核心体验不是只写题材名，而是包含用户会反复进行的行动或选择。
- 总体基调明确，且没有互相抵消却未排序的基调要求。
- 用户参与位置与能动性明确。
- RP 包承载形态明确，且没有因为存在锚点角色就把项目误判为真正单人卡。
- `card_entry` 已生成非空、非空白、非占位符的简短常驻成稿，说明整包用途、用户进入方式和模块协作意图，没有提前写任何角色档案或应由世界书调度的模块正文。
- 已锁定项目标题；承载模式足以判断最终使用标题还是唯一角色名。非真正单人项目的标题概括整包的世界、玩法、主题或体验，不以某个角色或单一地区名充当默认标题。
- 标题已经以 `positioning.project_title` 锁入决定账本，并同步写入 `project.project.display_name`；两处完全一致。旧项目的 `positioning.card_title` 可读，但新锁定一律使用前者。
- 项目规模和预期游玩跨度明确。
- 体验支柱已有优先级，后续发生冲突时可以裁决。
- 没有把世界观、角色、系统或 UI 的未决细节伪装成定位结论。

## 轮次输出格式

用户选择后使用：

````markdown
## 本轮已锁定
- 核心体验：[决定]
- [其他本轮决定]

## 本轮生成片段
<!-- validate: positioning.schema.json -->
```yaml
schema_version: 1.0.0
id: project_positioning
status: draft
# 实际输出必须替换为非空成稿，不得保留方括号占位符。
card_entry: "[整包用途、用户入口与模块协作意图；不写任何角色档案]"
premise: "[一句话命题]"
target_users:
  - "[目标用户]"
card_mode: pending
user_role:
  label: "[高层参与位置]"
  agency: "[能动性摘要]"
  description: "[参与方式说明]"
experience_pillars:
  - id: core_experience
    priority: 1
    description: "[中文说明]"
tone:
  primary: "[主基调]"
  secondary: "[辅助基调]"
expected_span: pending
scope_notes: []
source_refs: []
```

同时把本轮确认的标题写入项目账本；不要给 `positioning.yaml` 再增加重复标题字段：

```text
project.project.display_name = "[已锁定项目标题]"
decision positioning.project_title = "[同一个标题]"
```

使用 Forge 时可执行 `state <workspace> lock positioning.project_title "[已锁定项目标题]"`；该操作会同步 `project.project.display_name`。定位完成前再次核对两处一致。

## 本阶段检查
- 已满足：[X/Y 项]
- 仍缺少：[仅列定位项]
- 跨阶段待办：[有则列出]

## 下一批问题
[只问定位问题；充分时改为阶段总汇]
````

## 示例片段

用户选择“悬疑为主、慢热关系为辅；用户是受限制但能主动调查的逃票者；长期章节式互动”后：

<!-- validate: positioning.schema.json -->
```yaml
schema_version: 1.0.0
id: project_positioning
status: locked
card_entry: "这是一个以封闭列车调查为核心的长期互动 RP 项目。用户以受规则约束的主动调查者进入，通过证据、选择与后果推进章节；角色、地点与规则由绑定世界书按当前上下文提供。"
premise: "用户作为身份随时可能暴露的逃票者，在封闭列车中主动调查循环真相，并与掌握规则的关键人物建立缓慢变化的关系。"
target_users:
  - "偏好主动调查、长期后果与慢热关系的用户"
card_mode: world_scenario_with_anchor_character
user_role:
  label: "逃票者"
  agency: "受规则约束的主动调查者"
  description: "行动会受到列车规则与身份风险约束，但调查路线和关系策略由用户主动选择。"
experience_pillars:
  - id: mystery_investigation
    priority: 1
    description: "通过可验证线索推进真相，而非等待角色单向揭晓。"
  - id: slow_burn_relationship
    priority: 2
    description: "关系变化来自长期行为后果，不因单次示好突变。"
  - id: identity_pressure
    priority: 3
    description: "隐藏身份持续影响路线、对话与风险选择。"
tone:
  primary: "封闭空间悬疑"
  secondary: "克制的关系张力"
expected_span: long_form_chaptered
scope_notes:
  - "采用带锚点角色的世界/场景项目承载，由完整世界设定支持长期章节推进。"
source_refs: []
```

该片段没有定义列车规则、列车长性格或怀疑值算法；这些分别属于世界观、角色和系统阶段。

## 阶段总汇

总汇应包含：

- 完整合并后的定位片段。
- `project.project.display_name` 与 `positioning.project_title` 的一致性结果。
- 已锁定的体验优先级。
- 尚存的定位层冲突或可选增强项。
- 已记录但未展开的跨阶段信息。
- 建议启用或跳过哪些可选阶段及理由。

新建项目在这份定位总汇被锁定后，才初始化其指定工作区并保存源码。正常模式由用户确认锁定；完全放权模式由 AI 报告方案和理由后锁定。

## 下一阶段建议

- 有现成材料：推荐进入“材料整理”，先建立来源权重和保留策略。
- 无现成材料：跳过材料整理，推荐进入“世界观”。
- 只有极小范围的单场景 RP 项目：仍推荐先做最小世界观，至少锁定会约束行为的通用规则。
- 修改或审查项目：根据目标文件路由，但先消费材料整理结果；不要因为已有卡就跳过依赖检查。

正常模式下由用户确认下一阶段。若当前授权覆盖阶段切换，报告推荐与理由后直接锁定路线。
