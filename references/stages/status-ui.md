# 状态栏 / UI 阶段（可选）

本阶段直接创作与 RP 配套的消息内前端，不用通用组件编译器替作者生成一套模板化仪表盘。

## 第一批必须问

> 配套 UI 希望做到轻型、轻中型、中型、重型还是超重型？

同时询问题材视觉方向、主要设备、最常查看/操作的内容，以及开局入口与状态界面是否都需要。给出结合当前项目的明确推荐。

等级衡量的是完成度、华丽度、主题沉浸、交互与 JS 深度：

| 等级 | 含义 |
| --- | --- |
| 轻型 | 完整、成熟、主题统一；交互克制但不简陋 |
| 轻中型 | 拟物感、行动按钮、宿主联动和反馈明显增强 |
| 中型 | 产品级信息架构、筛选、弹窗、搜索、动效与多类数据视图 |
| 重型 | 强主题演出、复杂交互、深度宿主协作和丰富趣味功能 |
| 超重型 | 同层/0层游玩应用；消息 HTML 成为主要游玩表面，具备应用级路由、状态、持久化与生命周期 |

等级不规定页数、字段数、正则数或代码行数。轻型也可以是一份很长、很完整的 HTML；超重型也不能用堆代码冒充体验。

## 先定功能面，不拆碎组件

通常优先形成两份完整功能面：

1. **完整开局应用**：版本/世界/更新/作者留言/指南/开场选择/创角/预览/确认入局；
2. **完整状态应用**：在一个统一界面内承载本项目需要的状态、任务、物品、关系、情报、地图、调查、事件等内部页面。

检定结果、临时选项、通知等仅在生命周期不同且独立出现时再拆成单独正则。不要把一个功能页里的每张卡片、标签或按钮各自做成独立 HTML/正则。

## 维护源码

推荐：

```text
src/runtime/ui/
  开局界面.html
  状态界面.html
  检定结果.html          # 仅按需
```

每份是完整 HTML 文档或可构建为完整文档的小项目，通常包含：

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width,initial-scale=1">
  <style>/* 项目专属完整样式 */</style>
</head>
<body>
  <!-- 一个功能面内的全部页面与组件 -->
  <script type="module">/* 真实交互、数据读取和宿主联动 */</script>
</body>
</html>
```

不要把 HTML 重新拆成 `ui.yaml + theme.yaml + components/*.yaml` 再由通用代码合成。确有现成前端工程时可以编译，但构建产物必须是项目专属完整 HTML，而不是通用模板。

## 数据与运行链

设计前明确：

```text
原始数据来自哪里
→ 当前楼层如何读取
→ 哪些值是持久状态、草稿、UI 状态或派生显示
→ 何时刷新
→ 用户动作写到哪里
→ 失败、空值、加载与降级怎样显示
```

MVU 状态栏通常通过消息 HTML/iframe 读取当前楼层 `stat_data`，等待真实 MVU 就绪，并监听实际更新事件。非 MVU 状态栏可捕获模型输出的稳定状态块。不要让正则凭空“把变量变成 HTML”，也不要把示例初值硬编码成运行数据。

按钮可以读取/写入消息或变量、调用 slash command、填充/发送 SillyTavern 输入框、打开弹窗、操作世界书或调用宿主 API。使用父页面 DOM 和私有 API是允许的；记录版本耦合和失败表现并真机验证即可。

## 中文玩家体验

- 玩家可见标题、标签、空状态、错误与按钮默认使用自然中文；
- 不直接暴露 `runtime_path`、snake_case、内部 ID 或英文枚举；
- 中文字体、行高、字重、标点、换行与长文本经过实际检查；
- 主要信息优先，次要信息用标签页、折叠、抽屉或详情层渐进展示；
- 触控区域、键盘焦点、反馈、滚动、窄屏、软键盘和减少动画均按实际功能处理；
- 视觉主题来自世界本身，而不是默认蓝色仪表盘或代码工程风。

## 生命周期与验证

检查真实消息渲染、iframe/Blob URL 模式、脚本重复注册、楼层身份、编辑、Swipe、重载、聊天切换、窄屏、长中文文本、空数据、错误数据、按钮重复点击和控制台首个因果错误。

页面级常驻状态栏/面板仍不创建；本阶段所有常规 UI 位于聊天消息或用户明确选择的合法卡内载体。超重型同层前端也必须由角色卡携带，不能修改宿主本体。

## 完成门槛

- UI 等级与主题选择有明确理由；
- 完整功能面、内部导航和用户旅程清楚；
- 实际 HTML/CSS/JS 已生成，而非只有组件配置；
- 所有可见字段都有真实数据来源和中文显示映射；
- 所有按钮有真实处理、反馈和失败状态；
- 正则触发标记、提示词分离和宿主依赖明确；
- 没有真实宿主证据时标记 `runtime: not_run`，但仍可构建候选交付物。
