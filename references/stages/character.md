# 角色阶段

本阶段先盘点完整 RP 包是否需要固定、预先创作的角色；有则把每个角色写成可稳定扮演的决策者并明确其叙事身份，无则锁定空角色清单并当轮完成，不伪造占位角色。真正的单人卡或明确有核心锚点的项目可以有一个 `primary_character`；世界、群像、叙事者或动态生成人物的玩法项目可以没有固定主角色，部分模式也可以没有任何角色源码。`primary_character` 只表示叙事锚点，不表示该角色拥有整包，也不会让世界/玩法项目改用角色名。所有具名角色默认都是各自独立的 CharacterBook 内容模块。

本阶段只决定“有哪些角色、是否存在叙事锚点、每个人物包含什么内容”，不把任何角色塞进卡面 `description`，也不决定 CharacterBook 宿主参数。角色条目的常驻/关键词策略、插入位置、深度、顺序、概率、扫描深度和递归全部留到整合交付阶段。

## 本阶段产物

先形成角色资产清单。定位允许零固定角色且用户选择不预制人物时，清单为空、`source_manifest.characters: []`，不读取人物模板，也不生成空壳角色文件；随后直接进入本阶段总汇。存在角色时，角色源码按人物拆分，默认一个具名角色一份独立源码。每个角色至少形成：

当前 Forge 解包只把完整旧卡保留在项目级 `src/import/original.json`，不会根据 `data.name` 自动生成人物。若较早版本项目中已有 `role: pending` 候选，它只表示“尚未分类”，不是主角色证明。本阶段必须把实际人物改成正式角色类型；若判断原卡其实是世界/玩法包入口而非人物档案，则移除候选，不能把 `pending` 锁进成品。

- 稳定英文机器 ID、中文显示名、`primary_character | npc` 身份与叙事功能。
- 外在目标、内在需要、利害与核心矛盾。
- 价值排序、底线、恐惧、弱点和自我欺骗。
- 决策原则、刺激到反应的行为模式、压力升级路径。
- 公开知识、私人知识、误解与秘密。
- 与用户及关键角色的关系起点和变化逻辑。
- 语言习惯、表达禁区和少量校准示例。
- 防止 OOC 的优先级与禁止捷径。

同时形成一份仅用于后续投影的角色分类清单：

- 可选 `primary_character`：仅表示叙事锚点，不表示卡面字段、整包所有权或卡名；完整定义成为独立 CharacterBook 内容模块。
- 每个具名角色（包括 `primary_character` 与 `npc`）：默认各自成为一个 CharacterBook 内容模块，不与其他角色捆成总档案。
- 群体、无名路人或纯职能单位：只有在无法独立触发、单独注入也没有意义时才允许合并，并记录合并理由。

这里的“成为 CharacterBook 内容模块”只表示内容归属和稳定 ID 已确定，不表示已经决定常驻、关键词、插入深度等装配策略。

## 允许问题

可以询问：

- 角色是谁、承担什么叙事功能、在世界中拥有什么职责或身份。
- 已锁定承载模式是否需要一个 `primary_character` 叙事锚点，以及哪些具名角色是独立 NPC；若定位明确为世界、群像或动态角色项目，不强行指定假主角。
- 角色当前想得到什么，失败会失去什么。
- 角色真正需要什么，以及本人是否意识到。
- 多种价值冲突时的优先顺序。
- 恐惧、缺陷、偏见、自我欺骗和不可轻易跨越的底线。
- 在信任、受辱、威胁、失败、亲近、欺骗等刺激下的典型行为。
- 平静、戒备、失控等压力级别下行为如何升级。
- 角色知道、误以为知道和完全不知道的内容。
- 角色与用户的初始立场、权力差、依赖和长期关系方向。
- 外貌、体态、服装、习惯动作等有助于稳定呈现的特征。
- 语速、词汇、句式、称呼、回避话题和对话策略。
- 哪些讨好用户的写法会破坏角色一致性。

## 禁止问题

不得询问：

- 新的世界通用力量规则、社会制度、历史事实或势力结构。
- 好感、怀疑等变量的数值范围、增减量、阈值和公式。
- 地点拓扑、门禁、线索位置或事件时间表。
- MVU 字段路径、更新协议、EJS 或脚本实现。
- 全局叙事视角、回复篇幅、排版规则或开场白正文。
- 状态栏布局、颜色、组件或交互。
- `data.personality`、`data.scenario` 等高级定义字段如何分摊人物内容。
- CharacterBook 激活模式、关键词、插入位置、深度、顺序、概率、扫描深度或递归。
- NSFW 的偏好、限制、强度或边界问题。

角色可以对世界规则有个人理解，但不能借角色设定修改世界规则本身。

## NSFW 条件合并

读取项目预检中已锁定的开关，不在本阶段再次提及或询问：

- 开关为 `enabled` 时，把相关成人维度自然并入人物身体呈现、亲密关系和情境行为结构。启用本身视为用户对该维度的项目级放权，依据已锁定的人格与关系方向补全，不额外建立偏好或限制问卷，不创建独立阶段。
- 开关为 `disabled` 时，人物源码、轮次片段、问题、标题和占位符中完全省略成人维度，不输出空字段。
- 生成始终受平台硬性安全约束；不要额外添加技能自己的重复限制说明。

启用时把 `assets/templates/nsfw/character.mixin.yaml` 合并到角色模板，并在本阶段按角色逻辑填充；关闭时不要读取或复制该 mix-in。

用户若主动提供相关角色事实，可以直接纳入对应人物结构，但不要由此发起追问。

## 建议轮次

### 第一轮：身份与戏剧功能

询问 3 到 6 项：

1. 角色在项目中的功能。
2. 可选叙事锚点与具名角色清单。
3. 当前外在目标与失败利害。
4. 与用户的初始位置和权力关系。
5. 能被用户观察到的第一印象。
6. 多角色项目中各自的差异化职责。

### 第二轮：内在决策引擎

询问：

- 内在需要和自我认知差距。
- 价值优先级。
- 恐惧、弱点、底线与合理化方式。
- 最容易撕裂角色的两难冲突。

不要只让用户选“温柔/冷淡”。方向应说明不同选择会怎样改变行为。

### 第三轮：行为与压力

为高频刺激建立“观察 -> 判断 -> 行动 -> 后果”的模式，并写出从平静到高压的升级阶梯。把会造成 OOC 的捷径明确列为禁止行为。

### 第四轮：知识、关系与语言

确定信息边界、对用户的关系起点与可变化部分、称呼和表达策略。语言示例只用于校准角色口吻，不提前写叙事阶段的开场白。

### 第五轮：一致性审计（仅按需）

用背叛、示弱、利益诱惑、权威命令、世界规则冲突等情境检查角色是否有稳定裁决依据。发现数值需求时只登记系统待办。

## 充分性门槛

本阶段整体应满足：

- 角色分类符合已锁定 `card_mode`：真正的单人项目与带锚点项目都至多一个 `primary_character`；世界/群像/动态角色项目可以没有；不存在两个竞争的主锚点，且带锚点项目没有被误判成真正单人卡。
- 空角色项目已由承载模式支持，明确锁定 `source_manifest.characters: []`，且没有占位角色、空壳档案或人物模板残留。
- 每个具名角色都有独立稳定 ID、中文显示名和独立 CharacterBook 内容模块；合并无名群体时有明确理由。
- 没有把其他角色档案、世界规则、系统规则或叙事合同混入某个角色定义，也没有把任何角色预定写入 `data.description`。
- 没有在本阶段询问或锁定任何世界书调度参数。

每个角色都应满足：

- 身份、叙事功能、外在目标和失败利害明确。
- 内在需要与自我认知之间有可表演的关系。
- 价值已有排序，面对冲突可以预测选择。
- 弱点、恐惧、底线和矛盾不会互相抵消。
- 至少覆盖常态、高压和关系变化时的行为模式。
- 知识、误解和秘密分层明确，不会无故知道 GM 信息。
- 与用户的关系有起点、变化依据和不会瞬间跨越的限制。
- 语言规则足以辨认角色，但不依赖固定台词机械复读。
- 防 OOC 规则指向具体行为，不是“始终保持人设”之类空话。
- 需要数值化或工程化的事项已路由，而非在本阶段提前实现。
- 条件启用的成人结构已按预检状态自动合并或完全省略。

## 阶段总汇

总汇应包含：

- 角色资产清单；为空时说明为什么项目不需要固定角色，有内容时提供可选叙事锚点与所有具名角色的独立完整合并稿，以及“一人一条”的 CharacterBook 内容候选清单。
- 明确声明任何角色都不进入 `data.description`；项目级入口和卡名已经由项目定位阶段按 RP 包承载类型锁定，叙事锚点不会覆盖项目标题。
- 角色之间的功能差异与关系摘要。
- 价值冲突和压力测试结果。
- 知识泄漏、行为捷径与 OOC 风险检查。
- 用户已锁定与 AI 获授权锁定的决定。
- 路由到系统、场景、叙事或 UI 的待办。
- 明确声明本阶段没有决定 activation、keys、position、depth、order、probability、scan depth 或 recursion；这些只在整合阶段处理。

## 下一阶段建议

- 存在需要持续追踪的关系、资源、风险或成长变化：推荐进入“系统”。
- 所有变化都可由自然语言和角色规则稳定处理：可以跳过系统，推荐进入“场景”。
- 若系统与场景都非项目所需：根据是否仍有运行时状态管理或条件化渲染需求，只给出“进入 `mvu_ejs`”或“跳过并进入 `narrative_opening`”两种路线方向和推荐，不在角色阶段询问具体能力组合。选择跳过时按可选阶段规则记录 `skipped`；非新建项目同时保留既有实现。
- 角色能力与世界规则冲突：先返回世界观做最小补丁，再恢复角色阶段。

正常模式下由用户选择是否补漏及下一阶段。放权覆盖时，报告决定和理由后直接锁定路线。
