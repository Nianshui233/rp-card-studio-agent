# 场景阶段（可选）

场景是可进入、可感知、可行动、会变化的 RP 空间。它可以作为完整世界书条目保存，不必拆成数据库式坐标和流程图。

## 允许讨论

- 场景承担什么体验、平时如何运转；
- 外观、气味、声音、拥挤度、天气、照明和情绪；
- 常驻人物、来往人群、日程与场外变化；
- 可互动事物、入口出口、限制、风险、资源和线索；
- 表层可见信息、进一步发现和 GM/秘密信息；
- 事件怎样改变场景，场景怎样留下长期痕迹；
- 无图片、音频或 UI 时如何仅靠文本成立。

不重新设计人物人格、世界底层规则、变量实现、开场文风或 UI。

## 推荐源码

```yaml
名称: "旧检疫码头"
用途: "调查、黑市交易与势力冲突的交汇场所"

日常状态: |-
  白天由港务处封锁，夜里则被搬运工、走私客和无证医生分段占用。没有任何人在此真正掌握全貌。

氛围与感知:
  - "海雾贴着低矮仓房移动，灯光只能照出近处的水汽"
  - "铁轨尽头偶尔传来没有车轮的摩擦声"
  - "消毒水味掩不住旧木箱里的腥甜"

空间与行动:
  入口:
    - "港务处正门：需要通行证或熟人带领"
    - "退潮涵洞：只能在特定潮位通过"
  重点区域:
    - 名称: "封存仓"
      可做: [翻查登记、观察交接、寻找夹层]
      风险: "停留过久会被巡检与仓内异变同时注意"

常驻与变化:
  - "无证医生每隔三夜换一次临时诊所"
  - "走私团缺燃料时会从交易转向劫掠"
  - "港务处封锁升级后，普通搬运工会转移到南岸"

秘密:
  - "检疫记录删掉了一批从未下船的乘客"

可引出:
  - "港务处内部的记录篡改"
  - "潮雾异变与旧航线的联系"
```

需要事件、变量或媒体时写清语义需求，但不在场景文件里伪造 MVU 路径、URL 或前端组件。

## 完成门槛

- 场景不只是背景图片，而有日常、行动和变化；
- 表层信息与秘密分开；
- 入口、限制、风险和可继续推进的方向可判定；
- NPC/势力不因当前视角离开就停止行动；
- 可整体放入世界书，不依赖尚未实现的 UI 才能理解。
